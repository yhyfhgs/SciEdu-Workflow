## 可用关系类型
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

| 关系类型 | 语义含义 | 方向说明 | 典型示例 |
|----------|----------|----------|----------|
| `prerequisite` | A 是理解 B 的前置知识 | A → B（先学 A 才能学 B） | 极限定义 → 连续性定义 |
| `generalization` | A 是 B 的推广形式 | A ← B（A 比 B 更一般） | 一元积分 → 多元积分 |
| `specialization` | A 是 B 的特例 | A → B（A 是 B 的特殊情形） | Cauchy 列 → 收敛数列（在完备空间中） |
| `tests` | 题目 A 考查知识点 B | A → B | 求极限题 → 夹逼定理 |
| `illustrates` | 例题 A 展示/应用了知识点 B | A → B | 例 1.3 → 定理 1.2 |
| `similar_to` | 题目 A 与 B 在方法和知识点上相似 | A ↔ B（对称关系） | 两道夹逼定理应用题 |
| `harder_than` | A 比 B 在难度上更高 | A → B（A 更难） | 复合函数极限 → 简单极限 |
| `applies_method` | 题目 A 使用了方法 B | A → B | 不等式证明 → 数学归纳法 |

## 推断规则与质量标准
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

### 推断准则

1. **prerequisite**: 仅当理解 A 是理解 B 的**必要前提**时才标注，避免标注过于间接的依赖关系
2. **tests / illustrates**: 需要仔细匹配题目**核心考查**的知识点，而非所有涉及的知识点
3. **similar_to**: 方法**和**知识点都相似才标注，仅主题相同但方法不同不算 similar
4. **harder_than**: 基于实际解题难度判断，而非题目长度或条件数量

### 置信度标准

| 置信度范围 | 适用场景 |
|------------|----------|
| **0.9-1.0** | 关系明确无疑，如定理与其直接推论 |
| **0.7-0.9** | 关系高度可能，基于内容分析可确信 |
| **0.6-0.7** | 推测性关系，有合理依据但不完全确定 |
| **< 0.6** | **不要输出**——宁缺毋滥，不确定的关系不标注 |

### 质量控制

- 优先保证**精确率**（precision），宁可遗漏也不要标注错误关系
- 每对条目之间最多标注 **1-2 种**最核心的关系，避免过度标注
- 关系必须有实质性的学术意义，不要标注琐碎或显而易见的联系
