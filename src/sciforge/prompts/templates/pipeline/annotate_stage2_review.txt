6. **difficulty 校准**：与 §5 tag 子树中同分支同复杂度条目对齐（±1 以内）；过度偏离 → 调整

# 3. 输出格式（严格遵守）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**与 Stage2Annotate 完全一致的 6 字段 JSON**（单个 JSON 对象，无 markdown、无前后缀）。

即使 annotation 完全通过审核**也必须整体输出全部 6 个字段**（不能省略）。

| 字段 | 类型 | 约束 |
|---|---|---|
| `subject` | string | `english:中文`（§3.1） |
| `taxonomy_path` | string | 精确出现在 §6 Taxonomy 树；以 `{discipline_taxonomy_root}.` 开头或等于 `{discipline_taxonomy_root}` |
| `tags` | string[] | 至少 2 段；每段 `english:中文`；`tags[0] == {discipline_example_tag_root}` |
| `difficulty` | int | 1-10 |
| `question_type` | string\|null | `question` → 属 `{discipline_question_type_hints}`；`knowledge` → `null` |
| `methods` | string[] | 可空；每段同 tags 格式 |

## 3.1 段格式

正则 `^[a-z][a-z0-9_]*:[^\s:]+$`：
- english 部分：小写字母开头，`a-z 0-9 _`
- 冒号：ASCII 半角 `:`
- 中文部分：非空，无空白/冒号/斜杠

**禁用**：大写 `Math:` / 含空格 `math: 数` / 无冒号 `数学` / 全角冒号 `math：` / 多冒号 `math:数:学` / 零宽字符（U+200B/200C/200D/200E/200F/FEFF/2060）

## 3.2 完整示例

```
{{"subject":"real_analysis:实分析","taxonomy_path":"math.analysis.continuity.uniform","tags":["math:数学","analysis:分析","continuity:连续性","uniform_continuity:一致连续"],"difficulty":6,"question_type":null,"methods":["heine_cantor:海涅-康托尔定理"]}}
```

# 4. 注意要点
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

**A. 学科根（一票否决）**：即使 item 看似跨学科，本次标注的所属学科已固定为 `{discipline_name}`，**严禁换根**

**B. tag_tree 通用性比新颖性重要**：
- 复用已有段 > 新建段
- 同义异名**必须**合并到已有路径
- 新建段需能明显说出"为什么现有段不能覆盖"

**C. Taxonomy 是闭集**：LLM 不得自创路径；只能从 §6 给定的树中精确选择；若首轮选了不存在的路径 → 改为最接近的合法路径

**D. subject 整库稳定**：同一主题的条目 subject 字符串必须一模一样

**E. difficulty 对齐同类**：
- 评估维度：概念数、推理步数、前置深度
- 参考 §5 同分支条目的平均分数
- 偏离 > 1 → 调整

**F. 审核思路不外露**：所有推理在内部完成，输出只有最终 JSON

**G. 段数宽松**：一般不要因 tags/methods 差 1-2 段而否决；重点是**复用与一致**
