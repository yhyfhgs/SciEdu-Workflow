# 验证代码编写要求

### 基本规范

- 使用 `sympy`（符号计算）和 `numpy`（数值计算）作为主要工具
- 代码必须是**自包含**的，可独立运行
- 至少设计 **3 个**独立的测试用例
- 每个测试用例用 `print()` 输出 `"PASS"` 或 `"FAIL: <具体原因>"`
- 最后一行 `print()` 输出总结：`"ALL_PASSED"` 或 `"SOME_FAILED: N/M"`

### 验证策略选择

请根据题目类型选择合适的验证策略：

| 题目类型 | 验证策略 |
|----------|----------|
| **极限题** | 计算数列/函数在大 $n$ 或趋近点附近的数值，验证收敛趋势和极限值 |
| **等式/恒等式** | 代入多组随机数值（含边界值）验证等式成立 |
| **线性代数题** | 用具体矩阵实例化，验证所述性质（如秩、特征值、可逆性等） |
| **不等式** | 代入多组数值检查不等式是否成立，特别关注边界情况 |
| **证明题** | 检查若干特殊情形和边界情况，验证结论在这些情形下成立 |
| **微分方程** | 将解代入原方程验证，或用数值方法对比解的数值 |

### 代码质量要求

- 数值比较使用适当的**容差**（如 `abs(a - b) < 1e-10`），避免浮点精度问题
- 对可能的**数值异常**（如除零、溢出）进行防护
- 测试用例应覆盖**一般情况**和**边界情况**
- 代码中添加简要注释说明每个测试用例的验证目的
