## 0. 基线：已就绪的统一后端（实现完成，可直接对接）

多端产品**不重写后端**，全部对接以下已验证的统一契约（`src/sciforge/api/`）：

| 能力 | 端点 / 模块 | 状态 |
|---|---|---|
| 健康检查 | `GET /v1/health` | ✅ |
| 注册 / 登录（自定义 HMAC 签名 bearer access token，非 JWT） | `POST /v1/auth/register` `POST /v1/auth/login` | ✅ |
| 单题生成（QGen Harness 低延迟路径） | `POST /v1/generate` | ✅ |
| 求解 | `POST /v1/solve` | ✅ |
| 异步批量出题 + 任务查询 | `POST /v1/generate/batch` `GET /v1/tasks/{id}` | ✅ |
| 组卷 + 导出（Markdown/DOCX） | `POST /v1/papers` `POST /v1/papers/export` | ✅ |
| 用量与配额 | `GET /v1/usage` | ✅ |
| 练习行为记录（P4） | `POST /v1/behavior` | ✅ |
| 个性化推荐（难度/标签） | `GET /v1/recommend` | ✅ |
| 鉴权双通道：`X-API-Key`(B2B) / `Authorization: Bearer`(C 端) | `require_tenant` / `require_identity` | ✅ |
| 多租户行级隔离题库 | `MultiTenantStorageBackend`（`storage/multitenant.py`） | ✅ |

**契约稳定性承诺**：`/v1/*` 路径、请求/响应 schema（`api/schemas.py`）即多端共享契约。
任何前端先以此为准；后端新增端点须向后兼容（见 §7）。

## 1. 总体策略

1. **契约先行、一套 API 多端复用**：Web / App / 小程序共用同一 `/v1/*`；差异仅在 UI 与登录态获取。
2. **共享 TypeScript SDK**：抽出 `@sciforge/api-client`（纯 fetch + 类型），三端复用，杜绝各端重复实现鉴权/错误处理。从后端 OpenAPI（`/openapi.json`）用 `openapi-typescript` 生成类型，保证类型与后端契约同步。
3. **渐进式**：内置控制台（已 ✅）→ Web 生产前端 → App/小程序。每阶段独立可上线。
4. **私有化无差异**：私有化实例跑同一镜像 + 同一前端，仅指向隔离后端。

```
              ┌─────────── 共享 TS SDK (@sciforge/api-client) ───────────┐
   Web(Next)  ├── App(RN/Expo) ── 小程序(Taro) ── 内置控制台(已✅)         │
              └────────────────────────┬─────────────────────────────────┘
                                       ▼   统一 /v1/* 契约 + signed bearer/API Key
                          ┌──────────── API Gateway ────────────┐
                          │  鉴权 · 限流配额 · 计费 · 路由         │
                          └──────────────┬───────────────────────┘
                          统一后端(生成编排 + 题库 + SaaS 元数据 + PG)
```

## 2. 模块 A — Web 生产前端（Next.js 15）🔴

**目标**：替代内置控制台的生产级 Web，对接 §0 全部端点。独立 Node/npm 项目（不入本 Python 仓或作 `web/` 子目录 monorepo）。

### A.1 技术栈
- Next.js 15（App Router）+ TypeScript + Tailwind + shadcn/ui（对齐 `Docs/12`）
- 数学渲染：KaTeX（`rehype-katex` / 客户端 `auto-render`）
- 状态：Zustand（轻）或 TanStack Query（服务端状态/缓存）
- 鉴权态：当前 signed bearer token；生产前端优先由 BFF 写 `httpOnly` cookie，refresh 见 §5

### A.2 目录结构（建议）
```
web/
├── app/                      # App Router
│   ├── (auth)/login,register
│   ├── (app)/generate        # 出题工作台
│   ├── (app)/papers          # 组卷 + 导出
│   ├── (app)/practice        # 做题 + 行为上报 + 推荐
│   ├── (app)/usage           # 用量/计费
│   └── layout.tsx
├── lib/api/                  # = @sciforge/api-client（或 workspace 包）
│   ├── client.ts             # fetch 封装 + 鉴权头 + 401 处理
│   ├── types.ts              # openapi-typescript 生成
│   └── endpoints.ts          # generate/solve/papers/recommend/...
├── components/               # QuestionCard / LatexBlock / PaperBuilder / RadarChart
└── store/                    # auth、当前会话
```

### A.3 关键页面与对接
| 页面 | 调用 | 备注 |
|---|---|---|
| 登录/注册 | `/v1/auth/*` | 存 token，错误码 401/409 提示 |
| 出题工作台 | `/v1/generate`，批量 `/v1/generate/batch`+轮询 `/v1/tasks/{id}` | LaTeX 实时渲染；展示 verified 徽章、难度 |
| 组卷 | `/v1/papers` 预览 → `/v1/papers/export` 下载（blob） | 导出 MD/DOCX，PDF 待后端补（§7） |
| 做题/练习 | `/v1/recommend` 拉题 → 作答 → `/v1/behavior` 上报 | 形成"推荐→练习→画像更新"闭环 |
| 用量 | `/v1/usage` | 配额进度条；接近上限提示升级 |

### A.4 部署
- Vercel（SaaS）或自托管 Node。环境变量 `NEXT_PUBLIC_API_BASE` 指向网关。
- 私有化：与后端同机 `docker compose`，前端静态导出（`next build && next start` 或 `output: 'export'`）。

### A.5 验收
注册→生成→组卷导出→做题→推荐→用量 全流程可视化通过；移动端响应式；LaTeX 正确渲染。

## 3. 模块 B — App（React Native / Expo）🔴

**目标**：iOS/Android 原生体验，复用统一 API + 共享 SDK。

- **栈**：Expo（最快上架路径）+ TypeScript + `@sciforge/api-client`（同 Web）。
- **数学渲染**：`react-native-katex` 或 WebView 注入 KaTeX。
- **鉴权**：token 存 `expo-secure-store`；登录复用 `/v1/auth/*`；Apple/微信第三方登录见 §5🔑。
- **离线**：题目/讲义本地缓存（SQLite/MMKV）；行为离线队列，联网补传 `/v1/behavior`。
- **差异化**：推送通知（每日练习提醒）、错题本本地化。
- **上架**🔑：Apple Developer 账号、Google Play 账号（资质 + 费用）。

**验收**：TestFlight/内测包跑通登录→推荐做题→行为上报→离线补传。

## 4. 模块 C — 微信小程序（Taro / uni-app）🔴🔑

**目标**：微信生态内零安装触达。

- **栈**：Taro（React 语法，可与 App 共享部分组件）或 uni-app。
- **数学渲染**：小程序无 DOM → 用 `mp-html` + MathJax SVG 预渲染，或服务端把 LaTeX 渲成 SVG/图片下发（建议后端补 `render` 端点，见 §7）。
- **登录**🔑：`wx.login()` 拿 `code` → 后端 `POST /v1/auth/wechat`（待建，§7）用 AppID/AppSecret 调微信 `code2session` 换 `openid`+`unionid` → 绑定/创建用户 → 发本系统 access token。**需微信小程序 AppID/AppSecret + 主体资质**。
- **配额/计费**：复用 `/v1/usage`；小程序内虚拟支付须走微信支付（合规）🔑。

**验收**：开发者工具内登录→出题→做题闭环；体验版真机验证。

## 5. 模块 D — 统一身份与跨平台登录 🟡🔑

现状：✅ 用户名/密码 + 自定义 HMAC 签名 access token（`api/security.py`，不是 JWT）。补齐多
identity 绑定、refresh/吊销与第三方登录。

### D.1 数据模型（后端，🔴 待建）
扩展 `SaasStore`（或 PG）：
```sql
CREATE TABLE user_identities (
  user_id TEXT NOT NULL,
  provider TEXT NOT NULL,          -- password / wechat / apple / phone
  external_id TEXT NOT NULL,       -- openid+unionid / apple sub / 手机号
  UNIQUE(provider, external_id)
);
```
一个 `user_id` 绑多 identity → 一处注册处处登录（微信 UnionID 跨小程序/公众号/App 同一身份）。

### D.2 端点（后端，🔴 待建，见 §7）
- `POST /v1/auth/wechat`（code → unionid → access token）🔑
- `POST /v1/auth/apple`（identityToken 校验 → access token）🔑
- `POST /v1/auth/phone`（短信验证码）🔑（短信服务商）
- `POST /v1/auth/refresh`（refresh token 轮换；现仅 access token，需加 refresh 表/TTL）

### D.3 Token 策略
access（短 TTL，现有）+ refresh（长 TTL，可吊销）。`sign_token` 已支持 `exp`；refresh 需落库支持吊销。小程序用 `wx.checkSession` + 静默刷新。

**外部依赖**🔑：微信 AppID/Secret、Apple Sign-in Key、短信服务商密钥。本地用 mock provider 验证流程，凭据就绪后接真实。

## 6. 模块 E — 生产网关适配 🟡

现状：✅ 鉴权 + 配额(429) + 计费埋点（`require_tenant` + `record_usage`）已在 FastAPI 内。生产强化：

| 能力 | 现状 | 生产补强 |
|---|---|---|
| 鉴权 | ✅ API Key / signed bearer | 加 refresh/吊销、key 轮换 UI |
| 限流 | 🟡 仅按月配额 | 加**令牌桶**秒级限流（每租户/每 IP），独立中间件或网关层（Nginx/Kong/APISIX） |
| 计费 | ✅ usage_records | 接 `generation_traces` 聚合对账 + 账单导出 |
| 多区域/扩缩 | 🔴 单进程 uvicorn | 多 worker（gunicorn+uvicorn worker）→ k8s HPA；批量任务迁 Celery/RQ+Redis（现 BackgroundTasks） |
| 可观测 | 🟡 structlog + trace | 接 Prometheus/Grafana（SLA 仪表板，`Docs/14`）+ 告警 |
| 网关选型 | 🔴 | 反向代理统一 TLS/路由：Caddy/Nginx；规模上 Kong/APISIX 接管鉴权限流 |

**注**：本阶段后端逻辑大多已具备，主要是部署形态（容器化、worker、反代、监控）升级，详见 `Docs/13_部署与运维`。

## 8. 模块 F — 私有化 / 定制 API 隔离实例 🟡

- **物理隔离**：独立后端 + 独立题库（独立 SQLite 文件或独立 PG schema）+ 独立 SaaS DB，无跨租户查询路径（`MultiTenantStorageBackend` 已保证行级隔离；私有化更进一步用独立实例）。
- **交付物**：`docker compose`（API + 前端静态 + 可选本地模型）；白标（前端主题/Logo 可配）；离线可用（本地 LLM 或自带网关）。
- **数据不出域**：trace/计费仅落本地；无 LangSmith 等外发（已确认自研 HarnessGraph，不外发）。
- **License**🔑：私有化授权校验（离线 license 文件签名校验）。

## 11. 验收标准（总）
- 三端均通过同一 `@sciforge/api-client` 对接 `/v1/*`，无端各自实现鉴权。
- 跨平台统一登录：同一用户多端一致（UnionID/Apple sub 绑定到同一 `user_id`）。
- 私有化实例：离线可跑、数据不出域、白标可配。
- 全链路 SLA 可观测（`generation_traces` → 仪表板）。
- 后端契约新增全部有测试（`uv run pytest` 全绿）+ 类型同步（OpenAPI → TS）。
