# 数据模型与存储

> 版本: v4.1 | 日期: 2026-04-08

## 1. Pydantic v2 模型层次

所有数据结构统一使用 Pydantic v2 BaseModel 定义，贯穿 Pipeline、Agent、API 三层：

```
BaseModel
├── 枚举 (str, Enum)
│   ├── SubjectDomain   (math | physics | cs | chemistry | biology | chinese | english)
│   ├── Subject         (数学分析 | 高等代数 | 群论 | 组合数学 | 数论 | 拓扑学 | 复分析 | 概率论 | 实分析 | 泛函分析 | 常微分方程 | 其他 | ...)
│   ├── EducationLevel  (high_school | undergraduate | graduate)
│   ├── QuestionType    (calculation | proof | construction | true_false | choice | fill_blank | essay)
│   ├── KPType          (definition | theorem | lemma | corollary | concept | formula | law | principle | ...)
│   ├── VariantStrategy  (A1-A6, B1-B2)
│   ├── ExamType        (零试 | 一试 | 女子 | 期中 | 期末 | 高考 | 竞赛 | 模拟)
│   ├── VerifyStatus    (pass | fail | warn)
│   ├── DocumentFormat  (tex | markdown | pdf | docx | csv | pptx | epub)
│   └── MdBlockType     (definition | theorem | lemma | ...)
│
├── 核心实体
│   ├── Tag             (name, category, subject_domain, parent)
│   ├── KnowledgePoint  (id, title, content, type, subject, education_level, difficulty, tags, ...)
│   ├── Question        (id, content, difficulty, type, subject, education_level, tags, source, ...)
│   ├── Solution        (id, question_id, solution_latex, methods, confidence, ...)
│   └── DifficultyScore (10维 + overall + reasoning)
│
├── 来源元数据
│   ├── QuestionSource  (exam, type, year, month, number, book, chapter)
│   └── KPSource        (book, chapter, page, section)
│
├── 请求/响应
│   ├── GenerationRequest  (subject, topics, difficulty, type, strategy, ...)
│   ├── ContextBundle      (kps, refs, negatives, feedback)
│   ├── VerificationResult (passed, checks, suggestions)
│   └── GeneratedQuestion  (question, solution, score, verification, meta)
│
├── Pipeline 中间表示
│   ├── MdBlock / MdBlockV2 (block_type, content, format_spec, chapter/section_title)
│   ├── FormatSpec          (content_blocks[], section_pattern, source_type, answer_format)
│   ├── ContentBlockSpec    (block_type, open/close_pattern, number/title_group, is_paired_with)
│   ├── ContentMarkers      (formula_count, table_count, image_count, has_display_math, has_cjk)
│   ├── RawItem             (block_type, content_raw/latex, paired_item_id, content_markers)
│   ├── ExtractionReport    (strategy_used, items_found, coverage_ratio, quality_score)
│   ├── CorrectionResult    (corrected_content/latex, corrections[], quality A-F)
│   ├── ItemProcessingResult(correction + classification + item_subtype + difficulty)
│   └── UnifiedItemBase → KnowledgeItem(kp_type) / QuestionItem(question_type) / ExampleItem
│       (扁平化 3 类，通过枚举判别，无子类继承)
│
└── 配置
    ├── LLMConfig    (provider, model, temperature, ...)
    └── AppConfig    (storage_path, log_level, ...)
```

## 2. 核心模型定义

### 2.1 枚举类型

```python
class SubjectDomain(str, Enum):
    """学科大类"""
    MATH = "math"
    PHYSICS = "physics"
    CS = "cs"
    CHEMISTRY = "chemistry"
    BIOLOGY = "biology"
    CHINESE = "chinese"
    ENGLISH = "english"

class Subject(str, Enum):
    """学科细分领域（MVP 聚焦大学数学，可动态扩展）"""
    # 数学 - 大学（已实现）
    ANALYSIS = "数学分析"
    LINEAR_ALGEBRA = "高等代数"
    GROUP_THEORY = "群论"
    COMBINATORICS = "组合数学"
    NUMBER_THEORY = "数论"
    TOPOLOGY = "拓扑学"
    COMPLEX_ANALYSIS = "复分析"
    PROBABILITY = "概率论"
    REAL_ANALYSIS = "实分析"
    FUNCTIONAL_ANALYSIS = "泛函分析"
    DIFFERENTIAL_EQUATIONS = "常微分方程"
    OTHER = "其他"
    # 以下为多学科扩展预留（Post-MVP）
    # 物理 - 大学
    # MECHANICS = "力学"
    # ELECTROMAGNETISM = "电磁学"
    HS_THERMODYNAMICS = "高中热学"
    # CS
    DATA_STRUCTURES = "数据结构"
    ALGORITHMS = "算法"
    DISCRETE_MATH = "离散数学"

class EducationLevel(str, Enum):
    """教育阶段"""
    HIGH_SCHOOL = "high_school"
    UNDERGRADUATE = "undergraduate"
    GRADUATE = "graduate"

class QuestionType(str, Enum):
    CALCULATION = "calculation"
    PROOF = "proof"
    CONSTRUCTION = "construction"
    TRUE_FALSE = "true_false"
    CHOICE = "choice"
    FILL_BLANK = "fill_blank"       # 填空题（高中常用）
    SHORT_ANSWER = "short_answer"   # 简答题
    ESSAY = "essay"                 # 论述题（文科）

class KPType(str, Enum):
    DEFINITION = "definition"
    THEOREM = "theorem"
    LEMMA = "lemma"
    COROLLARY = "corollary"
    PROPOSITION = "proposition"
    EXAMPLE = "example"
    REMARK = "remark"
    PROOF_TECHNIQUE = "proof_technique"
    FORMULA = "formula"
    CONCEPT = "concept"             # 通用概念（物理定律、化学原理等）
    LAW = "law"                     # 定律（牛顿定律、热力学定律等）
    PRINCIPLE = "principle"         # 原理
    METHOD = "method"               # 解题方法/实验方法

class DocumentFormat(str, Enum):
    TEX = "tex"
    MARKDOWN = "markdown"
    PDF = "pdf"
    DOCX = "docx"
    CSV = "csv"
    PPTX = "pptx"
    EPUB = "epub"
```

其他枚举：`VariantStrategy` (A1-A6, B1-B2)、`ExamType` (零试/一试/女子/期中/期末/高考/竞赛/模拟)、`VerifyStatus` (pass/fail/warn)、`MdBlockType` (definition/theorem/lemma/...)。

> **学科拓展机制**: `Subject` 枚举可通过配置文件动态扩展。新增学科只需: (1) 添加 Subject 枚举值, (2) 添加学科标签体系, (3) 编写学科特定 prompt 模板。核心 Pipeline 和生成引擎代码无需修改。

### 2.3 核心实体

```python
class KnowledgePoint(BaseModel):
    id: str = Field(default_factory=lambda: str(uuid.uuid4()))
    title: str = ""
    content_latex: str = ""
    content_plain: str = ""
    kp_type: KPType = KPType.THEOREM
    subject_domain: SubjectDomain = SubjectDomain.MATH
    subject: Subject = Subject.ANALYSIS
    education_level: EducationLevel = EducationLevel.UNDERGRADUATE
    difficulty: int = Field(ge=1, le=10, default=5)
    tags: list[str] = Field(default_factory=list)
    prerequisites: list[str] = Field(default_factory=list)
    related_subjects: list[Subject] = Field(default_factory=list)  # 跨学科关联
    source: KPSource | None = None
    embedding: list[float] | None = None
    created_at: datetime = Field(default_factory=datetime.now)

class Question(BaseModel):
    id: str = Field(default_factory=lambda: str(uuid.uuid4()))
    content_latex: str
    content_plain: str = ""
    difficulty: int = Field(ge=1, le=10, default=5)
    difficulty_ai: float | None = None
    question_type: QuestionType = QuestionType.PROOF
    subject_domain: SubjectDomain = SubjectDomain.MATH
    subject: Subject = Subject.ANALYSIS
    education_level: EducationLevel = EducationLevel.UNDERGRADUATE
    tags: list[str] = Field(default_factory=list)
    source: QuestionSource | None = None
    is_generated: bool = False
    parent_id: str | None = None
    generation_meta: dict = Field(default_factory=dict)
    embedding: list[float] | None = None
    created_at: datetime = Field(default_factory=datetime.now)

class Solution(BaseModel):
    id: str = Field(default_factory=lambda: str(uuid.uuid4()))
    question_id: str = ""
    solution_latex: str = ""
    methods_used: list[str] = Field(default_factory=list)
    step_count: int = Field(ge=0, default=0)
    confidence: str = "medium"
    is_verified: bool = False
```

### 2.4 难度评分

```python
class DifficultyScore(BaseModel):
    concept_count: int = Field(ge=1, le=10, default=5)
    step_count: int = Field(ge=1, le=10, default=5)
    abstraction_level: int = Field(ge=1, le=10, default=5)
    technique_novelty: int = Field(ge=1, le=10, default=5)
    condition_parsing: int = Field(ge=1, le=10, default=5)
    computation_load: int = Field(ge=1, le=10, default=5)
    proof_structure: int = Field(ge=1, le=10, default=5)
    prerequisite_depth: int = Field(ge=1, le=10, default=5)
    multi_representation: int = Field(ge=1, le=10, default=5)
    metacognition: int = Field(ge=1, le=10, default=5)
    overall: float = 5.0
    reasoning: str = ""
```

10 维加权计算综合分，权重见 `WEIGHTS` 类变量（concept_count 0.15, step_count 0.15, abstraction_level 0.12, technique_novelty 0.12 等）。

### 2.5 请求/响应模型

```python
class GenerationRequest(BaseModel):
    subject_domain: SubjectDomain = SubjectDomain.MATH
    subject: Subject
    education_level: EducationLevel = EducationLevel.UNDERGRADUATE
    topics: list[str]
    difficulty_target: int = Field(ge=1, le=10)
    question_type: QuestionType
    strategy: VariantStrategy
    source_question: Question | None = None
    exclusion_ids: set[str] = Field(default_factory=set)
    count: int = 1

class ContextBundle(BaseModel):
    knowledge_points: list[KnowledgePoint] = Field(default_factory=list)
    reference_questions: list[Question] = Field(default_factory=list)
    negative_examples: list[Question] = Field(default_factory=list)
    feedback_from_previous_round: str = ""

class VerificationResult(BaseModel):
    passed: bool
    checks: dict[str, bool] = Field(default_factory=dict)
    suggestions: str = ""

class GeneratedQuestion(BaseModel):
    question: Question
    solution: Solution
    difficulty_score: DifficultyScore
    verification: VerificationResult
    generation_meta: dict = Field(default_factory=dict)
```

`ContextBundle` 提供 `to_prompt_block()` 方法，将知识点、参考题目、负样本格式化为 Markdown 注入 LLM 提示词。

### 2.7 Pipeline 通用中间模型

以下模型为当前 Pipeline 的核心中间表示（定义在 `src/mathforge/core/models.py`）：

| 模型 | 用途 | 阶段 |
|------|------|------|
| `ContentBlockSpec` | 单个内容块类型规格（open/close 正则、编号/标题提取组） | BlockSplitter |
| `FormatSpec` | 文档整体格式规格（content_blocks[], section_pattern, answer_format） | BlockSplitter (LLM 推断+缓存) |
| `MdBlockV2` | 按 FormatSpec 拆分后的语义完整内容块 | BlockSplitter → MetaExtractor |
| `ContentMarkers` | 每个条目的公式/表格/图片计数 | MetaExtractor |
| `RawItem` | 从 MdBlockV2 提取的原始条目（block_type, content_raw/latex, paired_item_id） | MetaExtractor |
| `ExtractionReport` | 提取报告（策略、条目数、覆盖率、质量评分） | MetaExtractor |
| `CorrectionResult` | LLM 校准修复后的内容（corrections[], quality A-F） | ItemProcessor |
| `ItemProcessingResult` | 校准 + 分类 + item_subtype + difficulty 的完整处理结果 | ItemProcessor |
| `UnifiedItemBase` | 统一条目基类（扁平化 3 类，枚举判别） | ItemUnifier |
| `KnowledgeItem` | kp_type 枚举判别的知识点条目 | ItemUnifier |
| `QuestionItem` | question_type 枚举判别的题目条目 | ItemUnifier |
| `ExampleItem` | 同时具有知识点和题目属性的例题条目 | ItemUnifier |

Pipeline 使用 `asyncio.Queue` 在三个异步 Task 间传递数据，不使用 LangGraph。

### 2.9 Pydantic 统一数据层

> **设计原则**: Pydantic 模型是 MathForge 中所有数据形状的唯一真理来源。

| 角色 | 说明 |
|------|------|
| **Pipeline 中间层** | 每个阶段（Python 和 LLM Agent）均消费和产出 Pydantic 模型。LLM Agent 被约束为输出匹配特定 Pydantic model schema 的 JSON。 |
| **Agent 通信** | LangGraph AgentState 字段类型为 Pydantic 模型。Agent 间数据交换始终通过验证过的 Pydantic 实例。 |
| **API 接口** | FastAPI 请求/响应 schema 即 Pydantic 模型，自动生成 OpenAPI 文档。 |
| **存储序列化** | 使用 `.model_dump_json()` / `.model_validate_json()` 进行 JSON 文件和 SQLite TEXT 列的序列化/反序列化。 |

## 3. 存储协议

```python
class StorageBackend(Protocol):
    """存储后端协议，支持文件 → SQLite 渐进迁移"""
    def save_question(self, q: Question) -> str: ...
    def load_question(self, id: str) -> Question: ...
    def search_questions(self, filters: dict) -> list[Question]: ...
    def save_knowledge_point(self, kp: KnowledgePoint) -> str: ...
    def load_knowledge_point(self, id: str) -> KnowledgePoint: ...
    def search_knowledge(self, filters: dict) -> list[KnowledgePoint]: ...
    def save_solution(self, sol: Solution) -> str: ...
    def load_solution(self, question_id: str) -> Solution | None: ...
```

### 3.1 文件存储后端（MVP）

`FileStorageBackend` 基于 JSON 文件存储，按 `subject_domain/subject/exam_type/year-month/` 层级组织目录。每个实体同时生成 `.json`（结构化数据）和 `.tex`（LaTeX 源码）两个文件。`IndexManager` 维护 `index.json` 索引文件，支持按学科、学段、标签、难度范围、题型等过滤查询。

## 4. 数据库方案

### 4.1 生产方案：SQLite + sqlite-vec

SQLite 作为嵌入式数据库，无需部署独立服务，配合 sqlite-vec 扩展实现向量检索：

| 组件 | 用途 |
|------|------|
| **SQLite** | 结构化数据存储（题目、知识点、标签、解答、用户记录） |
| **sqlite-vec** | 向量存储与余弦相似度检索 |
| **ChromaDB**（可选） | 开发阶段向量检索实验 |

**为什么不用 PostgreSQL**: 项目预期数据量为数千道题目、数百个知识点，SQLite 完全足够。SQLite 零运维、零部署成本、单文件备份，极大简化开发和部署流程。如未来数据量超出 SQLite 能力，可考虑 DuckDB 或托管数据库。

**核心表结构**（SQLite 语法）：

```sql
CREATE TABLE questions (
    id              TEXT PRIMARY KEY,
    content_latex   TEXT NOT NULL,
    content_plain   TEXT,
    difficulty      INTEGER CHECK(difficulty BETWEEN 1 AND 10),
    difficulty_ai   REAL,
    question_type   TEXT,
    subject_domain  TEXT NOT NULL DEFAULT 'math',   -- 学科大类
    subject         TEXT,                            -- 学科细分
    education_level TEXT NOT NULL DEFAULT 'undergraduate',  -- 教育阶段
    tags            TEXT,           -- JSON array
    source          TEXT,           -- JSON object
    is_generated    INTEGER DEFAULT 0,
    parent_id       TEXT REFERENCES questions(id),
    generation_meta TEXT,           -- JSON object
    created_at      TEXT DEFAULT (datetime('now'))
);

CREATE TABLE knowledge_points (
    id              TEXT PRIMARY KEY,
    title           TEXT,
    content_latex   TEXT,
    content_plain   TEXT,
    kp_type         TEXT NOT NULL,
    subject_domain  TEXT NOT NULL DEFAULT 'math',   -- 学科大类
    subject         TEXT,                            -- 学科细分
    education_level TEXT NOT NULL DEFAULT 'undergraduate',  -- 教育阶段
    difficulty      INTEGER,
    tags            TEXT,           -- JSON array
    prerequisites   TEXT,           -- JSON array
    related_subjects TEXT,          -- JSON array，跨学科关联
    source          TEXT,           -- JSON object
    created_at      TEXT DEFAULT (datetime('now'))
);

CREATE TABLE solutions (
    id              TEXT PRIMARY KEY,
    question_id     TEXT REFERENCES questions(id),
    solution_latex  TEXT,
    methods_used    TEXT,           -- JSON array
    step_count      INTEGER,
    confidence      TEXT,
    is_verified     INTEGER DEFAULT 0
);

CREATE TABLE tags (
    name            TEXT PRIMARY KEY,
    category        TEXT NOT NULL,
    subject_domain  TEXT,           -- 所属学科大类（NULL 表示通用标签）
    parent          TEXT REFERENCES tags(name)
);

CREATE TABLE subjects (
    id              TEXT PRIMARY KEY,
    name            TEXT NOT NULL,
    domain          TEXT NOT NULL,  -- 学科大类 (math/physics/cs/...)
    parent          TEXT REFERENCES subjects(id),
    education_levels TEXT,          -- JSON array: ["high_school", "undergraduate"]
    description     TEXT
);
```

向量索引通过 sqlite-vec 虚拟表实现：

```sql
CREATE VIRTUAL TABLE question_embeddings USING vec0(
    id TEXT PRIMARY KEY,
    embedding float[1536]
);

CREATE VIRTUAL TABLE kp_embeddings USING vec0(
    id TEXT PRIMARY KEY,
    embedding float[1536]
);
```

### 4.2 迁移路径

```
JSON 文件 (MVP)
     |
     v  (storage/migration.py: export_to_sqlite)
SQLite + sqlite-vec (生产)
```

每步迁移通过 `StorageBackend` 协议保证上层代码不变。迁移脚本从 JSON 文件批量导入 SQLite，并生成 embedding 向量索引。
