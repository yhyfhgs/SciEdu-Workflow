# 数据模型与存储

> 版本: v5.0 | 日期: 2026-04-11

所有数据结构统一定义在 `src/mathforge/core/models.py`，使用 Pydantic v2 BaseModel。

---

## 1. 模型层次

```
枚举
├── KPType        (definition | theorem | lemma | corollary | proposition | example | formula | ...)
├── QuestionType  (calculation | proof | construction | true_false | choice | fill_blank)
├── DocumentFormat (tex | markdown | pdf | docx | csv | pptx | epub)
├── Subject       (数学分析 | 高等代数 | 群论 | ...)
├── ExamType      (零试 | 一试 | 女子)
└── RelationType  (prerequisite | successor | corollary_of | ...)

存储实体（与 SQLite schema 一一对应）
├── KnowledgePoint
└── Question

Pipeline 运行时
├── MdBlockSource          # Producer 推入 queue 的单元
├── StoredItemBatch        # Task1 一次循环产物（用于日志）
└── FileExtractionState    # 断点恢复核心对象（持久化）

辅助
├── ItemRelation           # KP/Question.relations 字段（内存，不持久化）
├── DirectoryProgress      # 目录级断点
└── DifficultyScore        # 10 维难度评分（生成引擎重建时使用）
```

> 2026-04 清理：旧 4 阶段 pipeline 的中间模型（ExtractedItem / ChunkExtractionResult /
> ItemProcessingResult / CorrectionResult / TagSet 等）已被删除。Task1 直接把 LLM
> JSON 输出的 `items` 字段按 dict 处理并构造 KnowledgePoint/Question，不再经过中间类。

## 2. 核心实体

### 2.1 KnowledgePoint

```python
class KnowledgePoint(BaseModel):
    id: str = Field(default_factory=lambda: str(uuid.uuid4()))
    kp_type: KPType = KPType.THEOREM
    number: str = ""
    content: str = ""                    # 正文 (LaTeX+文本混排)
    proof_content: str | None = None     # 证明嵌入到主表
    proof_methods: list[str] = []
    difficulty: int = 5                  # 1-10
    subject: str = ""                    # 'english:中文' 单段
    taxonomy_path: str = ""              # dot 分隔: 'math.algebra.group_theory'
    tags: list[str] = []                 # 有序段列表: ['math:数学','algebra:代数',...]
    relations: list[ItemRelation] = []   # 内存字段，不持久化
    source_file: str = ""
    source_chapter: str = ""
    source_section: str = ""
    # 位置 / 顺序（pipeline 提取时填充）
    start_line: int = 0
    end_line: int = 0
    order_index: int = 0                 # 文件内全局递增（知识图谱构建用）
    page_start: int | None = None        # 1-based
    page_end: int | None = None
    quality_grade: str = "B"             # A/B/C/D（F 直接丢弃不入库）
    created_at: datetime = ...
```

### 2.2 Question

```python
class Question(BaseModel):
    id: str
    question_type: QuestionType = QuestionType.PROOF
    number: str = ""
    content: str = ""                    # 题目内容
    solution_content: str | None = None  # 解答嵌入
    solution_methods: list[str] = []
    answer: str = ""                     # 简答（选择题答案、填空答案等）
    difficulty: int = 5
    subject: str = ""
    taxonomy_path: str = ""
    tags: list[str] = []
    relations: list[ItemRelation] = []
    source_file: str = ""
    source_chapter: str = ""
    exam_type: str | None = None
    exam_year: int | None = None
    # 位置 / 顺序
    start_line: int = 0
    end_line: int = 0
    order_index: int = 0
    page_start: int | None = None
    page_end: int | None = None
    quality_grade: str = "B"
    is_generated: bool = False
    parent_id: str | None = None
    created_at: datetime = ...
```

### 2.3 关键约定

- **proof / solution 嵌入**：定理类的证明放在 `proof_content`；题目类的解答放在 `solution_content`。没有独立 `solutions` 表。
- **tags 是有序段列表**：每段 `english:中文` 格式，列表顺序代表从领域 (root) 到关键词 (leaf) 的一条路径。
- **`order_index` 单调递增**：Task1 内部维护计数器，跨 mdblock 连续。后续构建知识图谱时按 `(source_file, order_index)` 重建顺序。
- **`relations` 字段不持久化**：保留在 Pydantic 模型中以便后续手动构建图谱时填充，但 SQLite schema 不存。

## 3. Pipeline 运行时模型

### 3.1 MdBlockSource

Producer 把每个 5 页 batch 包装为 `MdBlockSource` 推入 queue：

```python
class MdBlockSource(BaseModel):
    file_path: str         # logical document 中的源文件
    page_start: int        # 1-based
    page_end: int          # 1-based, inclusive
    md_path: str           # checkpoint dir 中的 page_NNN-NNN.md
    md_text: str           # 已读取的 markdown 内容
    block_index: int       # 在该 logical document 中的全局序号 (从 0 起)
```

### 3.2 FileExtractionState

`pipeline/resume_state.py` 加载/保存的核心断点对象：

```python
class FileExtractionState(BaseModel):
    file_path: str
    file_hash: str
    phase: Literal["running", "completed"]

    # Producer 端
    vlm_batches_done: list[tuple[int, int, int]]  # (file_idx, page_start, page_end)
    failed_batches: list[tuple[int, int, int]]

    # Consumer 端
    current_block_idx: int                # 已完成入库的最后 block_index + 1
    line_offset: int                      # 已消费 + commit 的全局行数
    line_buffer_carry: list[str]          # buffer 中已注入行号的剩余行
    order_index_next: int
    tag_tree_json: str                    # TagTree 序列化 JSON
    saved_item_count: int
    failed_blocks: list[int]
    errors: list[str]

    started_at: datetime
    last_checkpoint_at: datetime | None
```

### 3.3 ExtractedItem / ChunkExtractionResult

Task1 内部使用的中间结构（不持久化）：见源码 `core/models.py`。`ExtractedItem` 包含 LLM 输出的 `item_type / number / content / proof / solution / line_start / line_end / structural_context`，由 Task1 进一步转换为 `KnowledgePoint` / `Question`。

### 3.4 StoredItemBatch

Task1 每次循环 yield 出来的进度对象：

```python
class StoredItemBatch(BaseModel):
    chunk_index: int
    line_range: tuple[int, int]
    kp_count: int
    question_count: int
    order_index_range: tuple[int, int]
```

## 4. 存储协议

```python
class StorageBackend(Protocol):
    def save_question(self, question: Question) -> str: ...
    def load_question(self, id: str) -> Question: ...
    def search_questions(self, filters: dict[str, object]) -> list[str]: ...
    def question_count(self) -> int: ...

    def save_knowledge_point(self, kp: KnowledgePoint) -> str: ...
    def load_knowledge_point(self, id: str) -> KnowledgePoint: ...
    def search_knowledge(self, filters: dict[str, object]) -> list[str]: ...
    def knowledge_count(self) -> int: ...


class BatchStorageBackend(StorageBackend, Protocol):
    def save_batch(
        self, kps: list[KnowledgePoint], questions: list[Question]
    ) -> int: ...

    def find_duplicates(self, content: str, item_type: str = "all") -> list[str]: ...
```

实现：`SQLiteStorageBackend`（`src/mathforge/storage/sqlite_backend.py`）。当前没有其他后端 — JSON 文件后端在 v6 重构中已删除。

## 5. SQLite Schema

完整 schema 见 `src/mathforge/storage/schema.sql`。核心表：

### 5.1 knowledge_points

```sql
CREATE TABLE knowledge_points (
    id TEXT PRIMARY KEY,
    kp_type TEXT NOT NULL DEFAULT 'theorem',
    number TEXT DEFAULT '',
    content TEXT NOT NULL DEFAULT '',
    proof_content TEXT,
    proof_methods TEXT DEFAULT '[]',         -- JSON
    difficulty INTEGER NOT NULL DEFAULT 5 CHECK(difficulty BETWEEN 1 AND 10),

    tags TEXT DEFAULT '[]',                  -- JSON 有序段列表
    -- 来源
    source_file TEXT DEFAULT '',
    source_chapter TEXT DEFAULT '',
    source_section TEXT DEFAULT '',
    -- 位置 / 顺序

    end_line INTEGER NOT NULL DEFAULT 0,
    order_index INTEGER NOT NULL DEFAULT 0,

    page_end INTEGER,

);
```

## 6. Pipeline checkpoint 文件结构

```
data/checkpoint/<file_hash>/
├── state.json                              # FileExtractionState
└── recognize/
    ├── file_000_<stem>/                    # logical doc 中的第一个分卷
    │   ├── page_001-005.md                 # 1-based 页号
    │   ├── page_006-010.md
    │   └── ...
    ├── file_001_<stem>/                    # 第二个分卷
    │   └── ...
    └── ...
```

`file_hash` = SHA-256 前 16 位，对单文件计算其内容；对多分卷按文件顺序拼接计算。`state.json` 通过 `tmp + os.replace` 原子写入，跨 Producer/Consumer 用 `asyncio.Lock` 保护。
