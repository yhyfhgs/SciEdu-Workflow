# 数据模型与存储

> 当前契约：内容库 schema **v14**；对话库与 QGen runtime schema v1。
> 权威实现：`src/sciforge/core/models.py`、`src/sciforge/storage/schema.sql`、
> `src/sciforge/storage/sqlite_backend.py`、`src/sciforge/api/conversations.py`、
> `src/sciforge/agents/runtime/store.py`、`src/sciforge/storage/saas.py`。

本文只描述当前可运行实现。知识条目的领域规则、发布门禁和验收指标见
[`21_知识库构建标准与数据契约.md`](21_知识库构建标准与数据契约.md)。

## 1. 设计原则

1. **内容与运行状态分库**：教育内容、对话产品状态、Agent checkpoint、账号计费不共享
   schema migration，也不让高频事件写入阻塞题库检索。
2. **原文、规范条目、治理信息分层**：原文件和 stage mirror 保存在 checkpoint；主表保存
   可检索正文；概念、评价和复核任务使用关系表追加。
3. **完备性与发布资格分离**：无法可靠提取的片段仍以 `uncertain/needs_patch` 入库，默认检索
   只发布 `accepted` 且通过治理门禁的条目。
4. **小多值内嵌，大关系规范化**：tags、options、难度维度等小对象存紧凑 JSON；概念映射、
   关系边、评价、事件使用独立表。
5. **幂等与追溯优先**：内容 hash、稳定 run/step/event id、不可变 checkpoint 和来源 locator
   共同保证恢复不重复调用、不重复计费、不重复发布。

## 2. 领域模型

所有跨模块对象使用 Pydantic v2。`Discipline` 当前允许
`math/physics/chemistry/biology/other`；具体 `kp_type/question_type/question_form` 由对应
`DisciplineSpec` 校验，不能把任意字符串当作已支持题型。

### 2.1 KnowledgePoint

| 字段组 | 字段 | 约束与用途 |
|---|---|---|
| 身份 | `id`, `discipline`, `kp_type` | UUID 文本主键；类型由学科白名单约束 |
| 编号 | `number`, `number_canonical`, `seq_chapter/section/index` | 原样标签与确定性派生排序字段分离 |
| 内容 | `content`, `proof_content` | 陈述与来源证明分离；没有证明时为 `NULL` |
| 分类 | `difficulty`, `subject`, `taxonomy_path`, `tags` | difficulty 1–10；tags 是有序 `english:中文` 数组 |
| 来源 | `source_file`, `page`, `start_line/end_line`, `start_char/end_char` | 定位到 checkpoint；字符范围未启用时为 0 |
| 顺序 | `order_index` | 全局稳定顺序；Stage3 禁止倒退 |
| 治理 | `ingestion_status` | `accepted/uncertain/needs_patch/rejected` |

### 2.2 Question

Question 继承相同的编号、分类、来源、顺序和治理语义，另含：

| 字段组 | 字段 | 约束与用途 |
|---|---|---|
| 题型 | `question_type`, `question_form` | 认知任务与载体形式正交，例如 `calculation + choice` |
| 题答 | `content`, `solution_content` | 题干与来源解答分离；不伪造缺失答案 |
| 结构化形式 | `options`, `correct_option`, `blanks` | JSON 选项、答案标签、空位数；不重复塞进题干 |
| 生成来源 | `is_generated`, `generator_model`, `generated_at`, `generation_session_id` | 可审计生成元数据 |
| 租户 | `tenant_id` | 空字符串为公共题；非空为私有租户题 |

`Solution` 是生成引擎的可发布输出模型，含 `solution_latex/solution_plain/methods_used/
self_check/confidence`。它不是独立内容表；pipeline 来源答案和生成题答案最终写入
`Question.solution_content`。对外输出教学化步骤和验证摘要，不保存模型私有 raw
chain-of-thought。

### 2.3 Pipeline payload 与 checkpoint

```text
MdBlockSource
  → ExtractedBatch
  → ReviewedItem
  → AnnotatedItem
  → ReviewedAnnotatedItem
  → KnowledgePoint / Question
```

`FileExtractionState(schema_version=2)` 保存 Task0 完成批次、滑动窗口 carry、下一 item id、
各 stage 计数和完成位、最后入库 id、TagTree 以及失败记录。它写入
`data/checkpoint/<file_hash>/state.json`，通过临时文件 + `os.replace` 原子替换；每个 stage 的
item mirror 用于恢复与审计。checkpoint schema 与内容库 schema 是两个独立版本号。

## 3. 内容库 schema v14

默认文件为 `data/sciforge.db`。连接启用 WAL、foreign keys 与 busy timeout；写入批次使用事务。

### 3.1 表目录

| 表 | 主键 / 唯一约束 | 职责 |
|---|---|---|
| `knowledge_points` | `id`; 非空 `content_hash` 全库唯一 | 规范知识条目 |
| `questions` | `id`; 非空 `(tenant_id, content_hash)` 唯一 | 来源题与生成题；租户作用域去重 |
| `discipline_tag_trees` | `discipline` | 学科受控 tag tree 快照 |
| `figures` | `id`; `(item_id,image_path)` 唯一 | 图像路径、caption、页码；不存二进制 |
| `item_relations` | `id`; `(src_id,dst_id,relation_type)` 唯一 | item 级 `tests/corollary_of/successor/...` 边 |
| `concepts` | `id` | taxonomy 驱动的稳定概念；状态 active/pending/deprecated |
| `concept_aliases` | `(discipline,branch,alias)` | 分支作用域别名，`WITHOUT ROWID` |
| `item_concepts` | `(item_id,concept_id,role)` | item↔concept 多对多，`WITHOUT ROWID` |
| `concept_relations` | `(src_concept,dst_concept,relation_type)` | 聚合概念图，`WITHOUT ROWID` |
| `item_evaluations` | `(item_id,rubric_version,source)` | 版本化质量与难度快照，`WITHOUT ROWID` |
| `review_queue` | `id`; `(item_id,reason,rubric_version)` 唯一 | open/in_progress/resolved/dismissed 人工治理任务 |
| `kp_fts`, `question_fts` | FTS5 rowid | 正文与 taxonomy 全文检索 |

跨 `knowledge_points/questions` 的 item id 无法由 SQLite 单一 FK 表达，因此
`figures/item_relations/item_concepts/item_evaluations/review_queue` 使用 `item_id + item_kind`
协议，并由存储层与验证命令检查悬挂引用。Concept 四表之间使用真实 FK 与级联删除。

### 3.2 `ingestion_status` 与无损升级

| 状态 | 含义 | 默认可发布 |
|---|---|---:|
| `accepted` | 边界、正文和分类满足摄取契约 | 还需通过概念/评价/审核门禁 |
| `uncertain` | 原始 span 已保存，但语义边界或合并置信度不足 | 否 |
| `needs_patch` | 已定位具体缺口，等待局部修补或人工确认 | 否 |
| `rejected` | 明确不是可发布条目；保留审计记录 | 否 |

相同去重域内，后续 `accepted` 校正可以原位提升非 accepted 占位，保持稳定 id、hash、关系和
引用；反向覆盖被禁止。正文或 taxonomy 更新由 FTS UPDATE trigger 同步，不需要重建全文索引。

### 3.3 发布查询

`QualityGateFilter` 在 SQL 的 `ORDER BY/LIMIT` 之前组合以下条件：

```text
ingestion_status = accepted
AND 没有关联 pending/deprecated concept
AND 没有当前 rubric 的 open/in_progress review task
AND 当前 rubric/source 的 extraction 与 solution 分数达到阈值
```

离线旧库可在“该 kind/rubric/source 整体尚无任何评价”时使用一次全语料 legacy fallback；
一旦开始评价，单条未评分记录不会被当作合格。认证租户题目视图关闭此 fallback，要求显式
评分，避免一个租户的评价状态影响另一个租户。

### 3.4 索引与空间策略

- 高频过滤列：discipline、type/form、subject、taxonomy、source、order、ingestion status、tenant；
- 图反向读取：relation src/dst、concept target、item/concept、review 工作队列；
- 质量门禁：rubric/source/quality/difficulty 复合索引；
- tags/options/difficulty details 等低选择性 JSON 不建立冗余索引；
- 原文件、完整 Markdown block、图像二进制、sandbox stdout 与 run event 不进入内容库；
- 大批量由 `executemany + 单事务` 写入，Stage3 小批聚合并在提交前恢复顺序。

## 4. 另外三类数据库

### 4.1 `data/conversations.db`

| 表 | 职责 |
|---|---|
| `conversations` | tenant 作用域会话元数据 |
| `conversation_messages` | user/assistant 消息、mode、metadata |
| `conversation_run_links` | 消息与 durable run 的稳定关联 |
| `conversation_artifacts` | question/solution/report 等产品产物元数据 |

它是 Chatbox 的产品历史，不保存 graph 中间状态。最终消息和 artifact 以 run id 构造稳定 id，
恢复后的重复交付是幂等读。

### 4.2 `data/qgen_runtime.db`

| 表 | 职责 |
|---|---|
| `agent_runs` | kind/status/input/output/metadata/budget/usage/cancel flag |
| `agent_run_steps` | 原子 step claim、状态、错误和用量 |
| `agent_run_checkpoints` | 完成节点后的不可变 state snapshot 与 next-node cursor |
| `agent_run_events` | 每 run 单调 sequence 的 append-only 事件 |

数据库触发器阻止 checkpoint/event 更新或删除。恢复从最近 checkpoint 的 `next_node` 继续，
已完成节点不重放；成功 run 的再次读取直接返回持久化 output。

### 4.3 `data/saas.db`

包含 `tenants/api_keys/users/usage_records/tasks/user_behavior`。API key 只存 SHA-256；用量与批量
任务按 tenant 记录。该库不保存题目正文，也不承担 QGen checkpoint。

## 5. 迁移与兼容

- 新库执行 `schema.sql` 并设置 `PRAGMA user_version=14`；
- 非空 v8–v13 库按 `_MIGRATIONS` 逐版本升级，单步提交，可在中断后幂等重试；
- v8 之前或核心表不完整的库拒绝猜测迁移，要求备份后 `--restart`；
- 未来版本 `user_version > 14` 拒绝降级写入；
- 修改字段、约束或索引时必须同时更新 schema、迁移链、Pydantic 模型和 round-trip 测试；
- 修改评价特征或权重必须升 `rubric_version`，不得覆盖旧评价。

## 6. 查询与写入规则

1. 所有 filter 由 allow-list 编译并参数化；text query 对 `%/_/\\` 转义。
2. 租户可见性、质量门禁、题型约束必须在排序和 limit 之前进入 SQL。
3. `INSERT OR IGNORE` 处理恢复重放；accepted promotion 只提升同一去重域内的占位。
4. 生成题保存时强制当前 tenant，不接受调用方伪造其他 tenant id。
5. `question_type` 与 `question_form` 都必须通过 `DisciplineSpec`；数据库 CHECK 只负责稳定的
   跨学科枚举，不在 SQL 复制快速演进的领域白名单。
6. 删除题目时清理无法由 FK 覆盖的 item relations；新增跨表关系必须配套悬挂引用测试。

## 7. 验证命令

```bash
# schema 与内容只读体检
uv run sciforge parse validate data/sciforge.db
uv run sciforge parse db-stats data/sciforge.db

# 存储、迁移、租户与恢复回归
uv run pytest tests/test_storage tests/test_api/test_run_recovery.py

# 全库质量
uv run ruff check src tests
uv run mypy
uv run pytest
```

声称迁移或摄取完成前，必须实际检查 `PRAGMA user_version`、最终 item/review 数、FTS 更新、
checkpoint 终态和验证报告；只看到命令退出 0 不等于数据契约已满足。
