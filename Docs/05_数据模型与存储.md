> - `_SCHEMA_VERSION=10`；`_MIGRATIONS` 提供 v8→v9→v10 增量 ALTER 链，旧库打开自动升级、不删库

>   + `seq_chapter` / `seq_section` / `seq_index`（结构化序号，编号 audit 用）
> - `questions` 新增 `question_form`（题目形式：choice/fill_blank/true_false/short_answer/subjective，
>   与 `question_type` 认知类别正交，#5）
> - `content_hash` 升级为 **UNIQUE 部分索引**（非空唯一），`save_batch` 用 `INSERT OR IGNORE` 写入去重（#8）
> - `discipline` 加 CHECK 约束；`difficulty` 保留 CHECK

>
> v5→v7 变更（历史）：
> - Pipeline 5 阶段重构：主线 payload 为 `ExtractedBatch` / `ReviewedItem` /
>   `AnnotatedItem` / `ReviewedAnnotatedItem`（均带 `source_file`）；`ExtractedSingleItem` 仅保留兼容说明
> - DB schema v7：保留 `source_file` 列（追溯来源），删除 `source_chapter` / `exam_type` / `exam_year`
> - 删除：`QuestionSource` / `ExtractedItem` / `ExtractedWindowPayload`
> - `FileExtractionState` 重写字段：`next_item_id` / `current_window_size` /
>   `consecutive_empty` / `stageN_count` / `stageN_completed` / `last_persisted_item_id`

所有数据结构统一定义在 `src/sciforge/core/models.py`，使用 Pydantic v2 BaseModel。

## 1. 模型层次

```
枚举
├── Discipline      (math | physics | chemistry | biology | other)
├── DocumentFormat  (tex | markdown | pdf | docx | csv | pptx | epub)
├── VariantStrategy / VerifyStatus / MdBlockType / MdSourceType
└── RelationType    (prerequisite | successor | corollary_of | ...)

# 注：kp_type / question_type / subject / exam_type 都是 str 字段，
# 合法值由 DisciplineSpec 在运行时约束（见 sciforge/disciplines/）

存储实体（与 SQLite schema v7 一一对应）
├── KnowledgePoint   # 保留 source_file；删除 source_chapter
└── Question         # 保留 source_file；删除 source_chapter / exam_type / exam_year

Pipeline 5 阶段 payload（stage 间通过 asyncio.Queue 传递）
├── MdBlockSource              # Task0 → q_md
├── ExtractedBatch             # Stage1Extract → q_raw（含 window_lines + item_ids/items）
├── ExtractedSingleItem        # 旧版单条 payload，保留兼容
├── ReviewedItem               # q_raw → Stage1Review → q_rev
├── AnnotatedItem              # q_rev → Stage2Annotate → q_ann
├── ReviewedAnnotatedItem      # q_ann → Stage2Review → q_done → Stage3Persist
├── StoredItemBatch            # 日志/进度（Stage3 入库产物）
└── FileExtractionState        # 断点恢复（含 schema_version=2）

辅助
├── ItemRelation           # KP/Question.relations（内存，不持久化）
├── DirectoryProgress      # 目录级断点
└── DifficultyScore        # 10 维难度评分（生成引擎用）
```

## 2. 核心实体

### 2.1 KnowledgePoint（schema v7）

```python
class KnowledgePoint(BaseModel):
    id: str = Field(default_factory=lambda: str(uuid.uuid4()))
    discipline: Discipline = Discipline.MATH
    kp_type: str = "theorem"             # DisciplineSpec.allowed_kp_types 约束
    number: str = ""
    content: str = ""                    # 正文（LaTeX+文本混排）
    proof_content: str | None = None     # 证明嵌入主表
    difficulty: int = 5                  # 1-10
    subject: str = ""                    # 形如 'real_analysis:实分析'
    taxonomy_path: str = ""              # dot 分隔 'math.analysis.continuity'
    tags: list[str] = []                 # 有序段列表 ['math:数学','algebra:代数',...]
    relations: list[ItemRelation] = []   # 内存字段，不持久化
    source_file: str = ""                # 源 logical_document 文件路径（追溯用）
    start_line: int = 0
    end_line: int = 0
    order_index: int = 0                 # = item_id（跨文件全局递增）
```

### 2.2 Question（schema v7）

```python
class Question(BaseModel):
    id: str
    discipline: Discipline = Discipline.MATH
    question_type: str = "proof"         # DisciplineSpec.allowed_question_types 约束
    number: str = ""
    content: str = ""
    solution_content: str | None = None
    difficulty: int = 5
    subject: str = ""
    taxonomy_path: str = ""
    tags: list[str] = []
    relations: list[ItemRelation] = []
    source_file: str = ""                # 源 logical_document 文件路径（追溯用）
    start_line: int = 0
    end_line: int = 0
    order_index: int = 0
```

**v7 相对 v5 删除的字段**：
- KP: `source_chapter`
- Question: `source_chapter`, `exam_type`, `exam_year`
- 注：`source_file` 曾在 v6 删除、v7 重新恢复

### 2.3 关键约定

- **proof / solution 嵌入**：定理的证明在 `proof_content`；题目的解答在 `solution_content`。无独立 `solutions` 表
- **tags 是有序段列表**：每段 `english:中文` 格式，列表顺序代表根→叶路径
- **`order_index` = `item_id`**：Stage1Extract 分配全局递增 id，Stage3Persist 严格按序入库
- **`relations` 字段不持久化**：仅内存字段

## 3. Pipeline 运行时模型

### 3.1 MdBlockSource

Producer 把每个 5 页 batch 包装为 `MdBlockSource` 推入 queue：

```python
class MdBlockSource(BaseModel):
    file_path: str         # logical document 中的源文件
    page_start: int        # 1-based
    page_end: int          # 1-based, inclusive
    md_path: str           # checkpoint dir 中的 page_NNN-NNN.md
    md_text: str           # 已读取的 markdown 内容
    block_index: int       # 在该 logical document 中的全局序号 (从 0 起)
```

### 3.2 FileExtractionState

`pipeline/resume_state.py` 加载/保存的核心断点对象：

```python
class FileExtractionState(BaseModel):
    file_path: str
    file_hash: str
    phase: Literal["running", "completed"]
    schema_version: int = 2               # 不兼容旧版时 raise StateSchemaMismatch

    # Task0 端
    vlm_batches_done: list[tuple[int, int, int]]
    failed_batches: list[tuple[int, int, int]]
    task0_completed: bool

    # Stage1Extract 运行状态
    current_block_idx: int                # 已消费 mdblock + 1
    line_offset: int
    line_buffer_carry: list[str]
    next_item_id: int                     # 全局自增 item id
    current_window_size: int              # 当前窗口大小（500~3000）
    consecutive_empty: int                # 连续 0 条计数

    # 各 stage 计数 / 完成
    stage1_extracted_count: int
    stage1_reviewed_count: int
    stage2_annotated_count: int
    stage2_reviewed_count: int
    stage3_persisted_count: int

    stage1_completed: bool
    stage2_completed: bool
    stage3_completed: bool

    last_persisted_item_id: int           # Stage3 保序断言用（起始 -1）
    failed_blocks: list[int]
    out_of_order_items: list[int]
    tag_tree_json: str                    # TagTree 序列化 JSON
    errors: list[str]

    started_at: datetime
    last_checkpoint_at: datetime | None
```

### 3.3 Stage 间 payload

```python
class ExtractedBatch(BaseModel):
    item_ids: list[int]
    items: list[SingleItemExtractLLM]    # 来自 llm_schemas
    window_lines: list[str]              # 原始 window（供 Stage1Review）
    window_line_range: tuple[int, int]
    window_last_line: int                # exercise near-tail validator 用
    block_index: int
    source_file: str
    page_start: int | None
    page_end: int | None
    stop_reason: str

class ReviewedItem(BaseModel):
    item_id: int
    item: SingleItemExtractLLM
    block_index: int
    page_start: int | None
    page_end: int | None

class AnnotatedItem(BaseModel):
    item_id: int
    item: SingleItemExtractLLM
    annotation: SingleAnnotationLLM
    block_index: int
    ...

class ReviewedAnnotatedItem(BaseModel):
    item_id: int
    item: SingleItemExtractLLM
    annotation: SingleAnnotationLLM       # 最终版
    block_index: int
    ...
```

### 3.4 LLM schema（`pipeline/llm_schemas.py`）

- `SingleItemExtractLLM`：单条条目（含 solution_status 二态）
- `BatchItemExtractPayloadLLM`：`{items, stop_reason, last_consumed_line, issues}` + exercise near-tail validator
- `BatchReviewPayloadLLM`：`{reviewed_items, issues}`，长度必须与输入 items 对齐
- `SingleItemExtractPayloadLLM`：旧版单条 schema，保留兼容
- `SingleAnnotationLLM`：单条标注

class StoredItemBatch(BaseModel):

## 4. 存储协议

```python
class StorageBackend(Protocol):
    def save_question(self, question: Question) -> str: ...
    def load_question(self, id: str) -> Question: ...
    def search_questions(self, filters: dict[str, object]) -> list[str]: ...
    def question_count(self) -> int: ...

    def save_knowledge_point(self, kp: KnowledgePoint) -> str: ...
    def load_knowledge_point(self, id: str) -> KnowledgePoint: ...
    def search_knowledge(self, filters: dict[str, object]) -> list[str]: ...
    def knowledge_count(self) -> int: ...


class BatchStorageBackend(StorageBackend, Protocol):
    def save_batch(
        self, kps: list[KnowledgePoint], questions: list[Question]
    ) -> int: ...

    def find_duplicates(self, content: str, item_type: str = "all") -> list[str]: ...
```

实现：`SQLiteStorageBackend`（`src/sciforge/storage/sqlite_backend.py`）。当前没有其他后端 — JSON 文件后端在 v6 重构中已删除。

## 5. SQLite Schema (v7)

完整 schema 见 `src/sciforge/storage/schema.sql`。核心表：

### 5.1 knowledge_points

```sql
CREATE TABLE knowledge_points (
    id TEXT PRIMARY KEY,
    discipline TEXT NOT NULL DEFAULT 'math',
    kp_type TEXT NOT NULL DEFAULT 'theorem',
    number TEXT DEFAULT '',
    content TEXT NOT NULL DEFAULT '',
    proof_content TEXT,
    difficulty INTEGER NOT NULL DEFAULT 5 CHECK(difficulty BETWEEN 1 AND 10),
    subject TEXT NOT NULL DEFAULT '',
    taxonomy_path TEXT DEFAULT '',
    tags TEXT DEFAULT '[]',                  -- JSON 有序段列表
    source_file TEXT NOT NULL DEFAULT '',    -- 源 logical_document 路径
    start_line INTEGER NOT NULL DEFAULT 0,
    end_line INTEGER NOT NULL DEFAULT 0,
    order_index INTEGER NOT NULL DEFAULT 0,
    content_hash TEXT DEFAULT ''

```

类似 knowledge_points，多 `question_type` / `solution_content`。

### 5.5 已删除的表

| 表 / 列 | 删除原因 |
|---|---|

## 6. Pipeline checkpoint 文件结构

```
data/checkpoint/<file_hash>/
├── state.json                              # FileExtractionState (schema_version=2)
├── recognize/
│   ├── file_000_<stem>/                    # logical doc 中的第一个分卷
│   │   ├── page_001-005.md                 # 1-based 页号
│   │   └── ...
│   └── file_001_<stem>/
│       └── ...
└── items/                                  # 5 阶段 mirror
    ├── stage1/item_000001.json             # ExtractedBatch 中单条 item snapshot
    ├── stage1_review/item_000001.json      # ReviewedItem
    ├── stage2/item_000001.json             # AnnotatedItem
    ├── stage2_review/item_000001.json      # ReviewedAnnotatedItem
    └── persisted/item_000001.json          # Stage3 完成标记
```

`file_hash` = SHA-256 前 16 位，对单文件计算其内容；对多分卷按文件顺序拼接计算。`state.json` 通过 `tmp + os.replace` 原子写入，跨 6 Task 用 `asyncio.Lock` 保护。
