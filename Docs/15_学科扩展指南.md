# 15 学科扩展指南

> 如何向 SciForge 添加新学科（以化学为例）

## 1. 学科在 SciForge 中的分层

SciForge 的学科模型分三层：

```
Discipline (顶层枚举，稳定 API)
    ↓
subject: str (二级字符串分类，由 LLM 自由生成)
    ↓
tags: list[str] (标签段列表，领域→大类→主题)
```

- **Discipline** 是稳定的 `StrEnum`，定义在 `src/sciforge/core/models.py`，当前包含 `MATH/PHYSICS/CHEMISTRY/BIOLOGY/OTHER`。新增一级学科需要改代码（罕见）。
- **subject** 是字符串，形如 `real_analysis:实分析` / `classical_mechanics:经典力学`。合法值由 `DisciplineSpec` 的白名单约束（可选）。
- **tags** 是有序段列表，每段 `english:中文`，例如 `["math:数学", "algebra:代数", "group_theory:群论"]`。

## 2. 新增学科的 5 步流程

### Step 1: 扩展 `Discipline` 枚举

如果新学科不在现有枚举中（`MATH/PHYSICS/CHEMISTRY/BIOLOGY/OTHER`），先在 `src/sciforge/core/models.py` 新增：

```python
class Discipline(StrEnum):
    MATH = "math"
    PHYSICS = "physics"
    CHEMISTRY = "chemistry"
    BIOLOGY = "biology"
    COMPUTER_SCIENCE = "cs"   # 新增
    OTHER = "other"
```

**注意**：`Discipline` 是稳定 API，影响数据库 `discipline` 列的取值。只增不删；废弃的学科直接映射到 `OTHER`。

### Step 2: 创建 Spec 文件

在 `src/sciforge/disciplines/specs/<name>.py` 定义 `<NAME>_SPEC`：

```python
# src/sciforge/disciplines/specs/chemistry.py
from sciforge.core.models import Discipline
from sciforge.disciplines.registry import DisciplineSpec

CHEMISTRY_SPEC = DisciplineSpec(
    discipline=Discipline.CHEMISTRY,
    display_name="化学",
    allowed_kp_types=(
        "definition",
        "law",
        "principle",
        "reaction",       # 化学特有
        "mechanism",      # 化学特有
        "formula",
        "experiment",
        "example",
        "remark",
    ),
    allowed_question_types=(
        "calculation",
        "reaction_equation",  # 化学特有
        "experiment_design",
        "explanation",
        "fill_blank",
        "choice",
    ),
    tag_root="chemistry:化学",
    prompt_vars={
        # extract_stage1_*.txt / annotate_stage2_*.txt / vlm_convert.txt 占位符
        "discipline_name": "化学",
        "discipline_document_expert": "化学文档结构化提取专家",
        "discipline_vlm_expert": "高精度化学文档转写专家",
        "discipline_item_types_text": (
            "- `definition` — 定义\n"
            "- `law` — 定律（如 质量守恒定律）\n"
            "- `reaction` — 化学反应\n"
            "- `mechanism` — 反应机理\n"
            "- `formula` — 化学公式（如 $PV=nRT$）\n"
            "- `experiment` — 实验说明\n"
            "- `example` — 例题（含 `solution` 字段）\n"
            "- `exercise` / `problem` — 练习/习题"
        ),
        "discipline_question_type_hints": (
            '- `calculation` — "计算..."、"求..."\n'
            '- `reaction_equation` — "写出反应方程式..."\n'
            '- `experiment_design` — "设计实验..."\n'
            '- `explanation` — "解释..."'
        ),
        "discipline_example_subject": "organic_chemistry:有机化学",
        "discipline_example_taxonomy": "chemistry.organic.hydrocarbons",
        "discipline_example_tag_root": "chemistry:化学",
        "discipline_tag_example": (
            '["chemistry:化学", "organic:有机化学", "hydrocarbons:烃类", "alkane:烷烃"]'
        ),
        "discipline_example_theorem_content": "质量守恒定律：化学反应前后，参加反应的各物质质量之和等于反应后生成的各物质质量之和。",
        "discipline_example_question_content": "计算 $1\\,\\mathrm{{mol}}$ 甲烷完全燃烧放出的热量。",
        "discipline_block_format_hint": (
            "定律/反应/公式格式：`**定律 X.Y (名称)**` 或 `**Reaction X.Y**`"
        ),
        "discipline_reasoning_style": "反应推导或表述风格",
        "discipline_figure_caption": "图 3.1：乙烷分子的 3D 结构",
    },
)
```

**关键约束**：`prompt_vars` 的 value 里**禁止**单独的 `{` 或 `}`。如果需要字面花括号（LaTeX `\mathrm{kg}`），写成 `{{` `}}` 预转义（见 `physics.py` 的 `discipline_example_question_content`）。

### Step 3: 注册到 registry

在 `src/sciforge/disciplines/registry.py` 的 `DisciplineRegistry.default()` 中添加：

```python
@classmethod
def default(cls) -> DisciplineRegistry:
    from sciforge.disciplines.specs.math import MATH_SPEC
    from sciforge.disciplines.specs.physics import PHYSICS_SPEC
    from sciforge.disciplines.specs.chemistry import CHEMISTRY_SPEC  # 新增

    return cls(
        {
            Discipline.MATH: MATH_SPEC,
            Discipline.PHYSICS: PHYSICS_SPEC,
            Discipline.CHEMISTRY: CHEMISTRY_SPEC,  # 新增
        }
    )
```

### Step 4: 补充生成路径 prompt 替换表（可选）

`src/sciforge/prompts/templates.py` 的 `_GENERATION_PROMPT_SUBSTITUTIONS` 字典为每个非数学学科定义了"数学→学科"的 str.replace 规则，用于 generation/solving/verification 下的 prompt。新学科需要补充：

```python
_GENERATION_PROMPT_SUBSTITUTIONS: dict[Discipline, list[tuple[str, str]]] = {
    Discipline.PHYSICS: [...],
    Discipline.CHEMISTRY: [
        ("资深大学数学教育专家", "资深大学化学教育专家"),
        ("数学家", "化学家"),
        ("原创数学题", "原创化学题"),
        ("数学题", "化学题"),
        ("数学", "化学"),  # 兜底，放最后
    ],
}
```

如果暂时跳过 Step 4，新学科会沿用数学的生成/求解 prompt——对于有一定迁移性的学科（如物理）也能跑，只是 LLM 看到的仍是"数学家"字样。

### Step 5: 添加测试

在 `tests/test_disciplines/test_registry.py` 补一条测试确认注册：

```python
def test_chemistry_spec_registered():
    spec = DISCIPLINE_REGISTRY.get(Discipline.CHEMISTRY)
    assert spec.display_name == "化学"
    assert "reaction" in spec.allowed_kp_types
    assert spec.prompt_vars["discipline_name"] == "化学"
```

## 4. 常见陷阱

### 陷阱 1: prompt_vars 花括号未转义

```python
# ❌ 错误：单个 {} 会让第二阶段 format() 抛 KeyError
"discipline_example_question_content": "设 $f: \\mathbb{R} \\to \\mathbb{R}$..."

# ✅ 正确：双括号预转义
"discipline_example_question_content": "设 $f: \\mathbb{{R}} \\to \\mathbb{{R}}$..."
```

单元测试 `test_prompt_vars_no_bare_brace` 会自动检出未转义的括号。

### 陷阱 2: allowed_kp_types 不完整

Stage3Persist 用 `spec.allowed_kp_types` / `allowed_question_types` 校验 LLM 输出的类型。如果学科的真实类型（如化学的 `reaction`）不在白名单，会被回退到列表首项。确保白名单覆盖该学科常见的所有类型。

### 陷阱 3: tag_root 与 LLM 输出不一致

`tag_root` 是 registry 里的声明，实际的 tag 由 LLM 在提取时生成。需要确保 prompt 里给了正确的首段示例，引导 LLM 输出匹配的 root。如果 LLM 输出了 `chem:化学` 而你的 tag_root 是 `chemistry:化学`，FTS 搜索会出现两套路径。可以通过 `prompt_vars["discipline_example_tag_root"]` 强制引导。
