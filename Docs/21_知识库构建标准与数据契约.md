# SciForge 知识库构建标准与数据契约

> 状态：schema v13 / Pipeline v11 M1–M7 实施基线
> 适用范围：教材、讲义、题集、试卷、论文式文档和结构化题库的摄取、治理与生成检索
> 权威实现：`core/models.py`、`storage/schema.sql`、`pipeline/stages/`、
> `pipeline/concept_linker.py`、`pipeline/evaluation.py`

本文规定“什么可以成为一个知识库条目”、如何保留来源、如何组织概念与评价，
以及不同学科、题型必须满足的最低完整性。它是数据验收契约，不是 prompt 建议；
LLM 输出违反本契约时，以 Pydantic、确定性校验器和 review queue 的结论为准。

## 1. 三层数据职责

| 层 | 权威内容 | 是否可覆盖 | 设计目标 |
|---|---|---:|---|
| 来源与 checkpoint | 原文件、适配后的 Markdown block、stage mirror、行/字符/页定位 | 否；新运行写新 hash | 可重放、可审计、保留修正证据 |
| 规范条目 | `knowledge_points`、`questions`、`figures`、`item_relations` | 只经版本化 pipeline | 紧凑检索、直接用于组卷/讲义 |
| 语义与治理 | concept 四表、`item_evaluations`、`review_queue` | 可追加新版本 | 跨书归一、质量门禁、人工闭环 |

原始文件和逐 block Markdown 不复制进 SQLite。数据库中的 `content` 是校正后的规范正文，
但必须由 `source_file + page/start_line/end_line + start_char/end_char` 回溯到 checkpoint。
图像二进制也不进 SQLite；`figures.image_path` 只保存资产路径与 caption/page。

## 2. 全局不可破坏不变量

1. **完整性优先**：任何具有独立语义或独立编号的定义、定理、公式、例题、练习、问题、
   证明、答案都必须被 marker ledger 计数。无法判定的条目进入复核，不得静默丢弃。
2. **一个条目一个语义单元**：共用一个编号且不可独立引用的题干与选项属于一条；
   有独立编号/独立结论的子题分别成条，并用关系边连接。
3. **题答配对**：题干留在 `content`；解答、证明和答案只放
   `solution_content` / `proof_content`。章末答案由 answer linker 回填，不创建伪知识点。
4. **来源可追溯**：`source_file` 非空；行区间必须满足 `start_line > 0` 且
   `end_line >= start_line`。启用字符 span 后，字符区间使用左闭右开语义。
5. **顺序稳定**：`order_index` 只按最终来源顺序分配，严格递增；并发、补丁和恢复不得改变
   同一来源的相对次序。原题号保存在 `number`，排序不得依赖其可解析性。
6. **规范身份与展示分离**：`taxonomy_path` / `concept_id` 是机器身份；
   `tags` 是有序的 `english:中文` 展示路径。不得用自由 tag 替代 concept。
7. **不伪造缺失内容**：原文没有解答时保留空值并进入质量门禁；不得让模型补写后冒充原文。
8. **版本化评价**：量规特征或权重改变必须升 `rubric_version`；历史评价只能追加，不能覆盖。

## 3. 输入格式与确定性预处理

| 输入 | Task0 策略 | 默认 LLM 调用 | 结构保留 |
|---|---|---:|---|
| Markdown / TeX | 原文直通 | 0 | 标题、公式、行号 |
| CSV / TSV | RFC 风格解析后按行块转 Markdown table | 0 | 引号、嵌入换行、重复表头、原始行范围 |
| XLSX | 安全读取 OPC ZIP/XML | 0 | sheet、共享字符串、公式与缓存值、布尔值 |
| HTML | 不执行脚本的结构解析 | 0 | 标题、段落、列表、链接、表格、code/pre |
| EPUB | container → OPF manifest/spine → XHTML | 0 | 章节顺序与 chapter locator |
| JSON / JSONL | 对象树或记录表格化，限制深度与分块 | 0 | key、record range、错误行号 |
| TXT / RST | 编码探测后按行块切分 | 0 | 原始文本与行范围 |
| 电子 PDF | 文字层探测后 PyMuPDF/pdftotext | 0 | 页范围 |
| 扫描 PDF / DOCX / PPTX | VLM 批量转写 | 每批 1 | 页范围、公式、图像引用 |
| PNG/JPEG/WebP/GIF | 单图 VLM 转写 | 每图最多 1（失败重试除外） | 图像来源与单块 checkpoint |

所有 ZIP 容器必须在解析前检查：压缩文件体积、条目数、总解压体积、单条目压缩比、
绝对路径和 `..` 路径穿越。所有文本/JSON 输入必须有限制的字节数、列数、深度和每块行数。

预处理只能做可逆或有证据的变换：换行/空白规范化、OCR 高置信替换、数学括号配平检测、
编号规范化、题型 marker 定位、表格转写。语义补写、条件猜测和答案生成不属于预处理。

## 4. 规范条目模型

### 4.1 KnowledgePoint

知识条目必须能被独立引用。允许的通用类别包括 definition、axiom、theorem、lemma、
proposition、corollary、formula、property、method、remark、example；最终白名单由
`DisciplineSpec.allowed_kp_types` 决定。

- `content`：完整陈述，包含全部条件、量词、符号定义和结论；不能只保留标题。
- `proof_content`：只存原文证明；定理无证明时为 `NULL`，评价系统标记 `missing_proof`。
- `number`：逐字保存“定理 3.2”等标签；`number_canonical/seq_*` 是确定性派生值。
- `subject/taxonomy_path/tags`：至少学科根合法；具体分支不确定时退回根并进入复核，
  不得硬塞某个示例 taxonomy。

### 4.2 Question

题目必须包含独立作答所需的全部条件。`question_type` 表示认知任务，`question_form` 表示载体，
二者正交。例如选择题可以同时是 calculation，证明题通常是 proof + short_answer。

- `content`：题干、必要数据、子问和图表引用；选项不得与题干重复。
- `options`：按原顺序保存完整选项；非选择题为空数组。
- `correct_option`：只保存标签（如 `A`、`AC`）；未知时为 `NULL`，不得猜测。
- `blanks`：填空位置数量；非填空题为 `NULL`。
- `solution_content`：答案和推导；只有最终数值而无过程时可保存，但质量分降低。
- 生成题必须写 `is_generated/model/generated_at/session_id/tenant_id`，不得伪装成来源题。

### 4.3 关系与概念

- item 级关系保存结构证据，例如 `tests`、`corollary_of`、`successor`；边必须带
  `source` 与 confidence。
- concept 身份由合法 taxonomy 路径确定性派生。alias 只在
  `discipline + branch` 作用域唯一，避免不同分支同名误合并。
- 一个 item 可以关联多个 concept，并用 `primary/defines/uses/prerequisite/tests` 表示角色。
- 未命中受控 taxonomy 的概念状态为 `pending`；默认不得进入生成池。

## 5. 分学科最低完整性

### 5.1 数学

- 定义必须保留定义域、量词、符号与等价条件。
- 定理/引理必须保留全部假设和结论；“显然”“类似可得”可保留，但不能替代缺失正文。
- 证明题分离题干与证明；多种证明方法在 `solution_content` 内以小标题保序。
- 公式必须保持 LaTeX 环境、上下标、矩阵维度、编号和适用条件。
- 几何题的图不是条件的替代品；正文中所有显式条件仍需转写，图写入 `figures`。

### 5.2 物理

- 数值、单位、有效数字、方向/坐标系、初始/边界条件必须保留。
- 物理量符号首次出现要能在同条目解释；常数取值和近似假设不能丢失。
- 实验题区分装置/步骤/观测/误差/结论；图表资产与 caption/page 关联。
- 解答的最终结果必须带单位；量纲不一致进入逻辑/数值复核。

### 5.3 化学

- 方程式保留计量系数、价态/电荷、物态、反应条件、催化剂和可逆符号。
- 结构式、谱图和实验装置作为 figure；正文必须保留可检索的物质名称与关键条件。
- 计算题保留物质的量、浓度、温压条件和有效数字；答案执行守恒与单位检查。
- 机理/路径的步骤不可合并成无序 tag，每一步作为解答结构或有序关系证据。

### 5.4 生物

- 区分实体、结构、过程、调控、证据和实验结论；相似术语不得因字符串相近而合并。
- 实验题保留自变量、因变量、对照、样本、重复、观测与结论边界。
- 图谱/系统发育树/通路图需要 caption 和原页；正文保留可独立理解的标注信息。

### 5.5 计算机与“其他”学科

当前 schema 将未注册学科映射为 `other`，但 taxonomy 首段仍须使用受控分支；正式扩展应先按
`Docs/15_学科扩展指南.md` 新增 DisciplineSpec，不得长期依靠自由字符串。

- 编程题必须保留输入、输出、约束、样例、语言/运行环境和资源限制。
- 解答区分算法、正确性论证、复杂度与代码；代码必须保留 fenced language。
- 人文/社会科学条目必须区分主张、证据、引用来源和适用语境；引文不得被模型改写后冒充原文。

## 6. 题型专项规则

| question_form | 必填证据 | 确定性检查 |
|---|---|---|
| choice / multiple_choice | 题干、全部选项；有来源答案时写标签 | 标签唯一、选项数、标签在范围内 |
| fill_blank | 完整句/式、空位数、来源答案 | `blanks >= 1`、答案数量兼容 |
| true_false | 可判定命题；来源答案 | 不能把解释文本当成命题 |
| calculation | 数据、单位、求解目标 | 单位/量纲、数值容差、代入复算 |
| proof | 假设、结论、证明要求 | 数学配平、关键蕴含链、可选 Lean 验证 |
| construction | 对象、约束、允许操作 | 构造后逐条验证约束 |
| experiment | 目标、材料、变量、步骤、评价指标 | 对照/重复/安全条件 |
| programming | I/O、约束、样例、资源限制 | 沙箱测试、边界样例、复杂度 |
| short_answer | 问题边界和评分点 | 答案覆盖评分点，不要求伪造长推理 |

## 7. 质量评价与发布门禁

`pipeline_auto` 量规不调用 LLM，至少保存：

- extraction quality；
- solution/proof completeness；
- 10 维 difficulty 及 overall；
- Bloom cognitive level；
- prerequisite depth、proof complexity；
- lecture suitability、cross-book generality；
- source、confidence、rubric version、evaluated time。

以下任一成立时进入 `review_queue`：提取质量低于阈值、题答/证明不完整、concept pending、
数学配平失败、编号/marker 覆盖异常、跨段合并不确定。review queue 只控制发布资格，不删除数据。
生成与推荐默认只读取 active concept 且通过当前 rubric 质量阈值的 item。

建议的验收指标：

| 指标 | 发布门槛 |
|---|---:|
| 强 marker 覆盖率 | 100% 已解释（提取或显式复核） |
| 来源 span 合法率 | 100% |
| item_id/order_index 倒退 | 0 |
| 未解释编号间隙 | 0（允许报告中的显式例外） |
| 选择题选项截断 | 0 |
| 有来源答案但未配对 | 0 |
| 非法 tag/taxonomy 根 | 0 |
| active concept alias 跨分支冲突 | 0 |
| 低质量 item 进入默认生成池 | 0 |

## 8. 存储与性能约束

- 主表只放高频过滤/展示字段；多值小数组使用紧凑 JSON，大关系使用规范化桥表。
- concept alias、item-concept、concept relation、evaluation 使用复合主键和
  `WITHOUT ROWID`，减少代理整数与重复索引空间。
- `content_hash` 非空唯一索引负责同正文去重；hash 只基于规范正文，不能因评价变化而改变。
- FTS 只索引正文和 taxonomy；大图、原文件、完整 checkpoint、执行日志不进入数据库。
- 索引必须对应真实读取路径：学科/类型/形式/来源/顺序、tenant、concept 反向边、
  rubric 质量门禁、review queue 工作队列。不要为低选择性 JSON 字段建立冗余索引。
- 批量写使用单事务和 WAL；Stage3 只允许按 order_index 正向提交。并发 worker 在入库前重排。
- schema 迁移只允许逐版本、幂等、可测试；量规和生成 run 数据采用追加式历史。

## 9. 运行与审计

```bash
# 新摄取；结构化格式在 Task0 不调用 LLM
uv run sciforge parse run <file-or-directory>

# checkpoint/schema 不兼容或明确要求全量重建时
uv run sciforge parse run <path> --restart

# 强制扫描 PDF 走 VLM（仅脏文字层时使用）
uv run sciforge parse run <pdf> --force-vlm

# 入库后只读体检
uv run sciforge parse validate data/sciforge.db
```

每次声称“完成摄取”前必须检查：最终 `state.json`、failed batches/blocks、
numbering/reconciliation report、concept pending 数、review queue、数据库 item 数与验证报告。
