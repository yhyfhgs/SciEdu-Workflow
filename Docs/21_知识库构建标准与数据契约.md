# SciForge 知识库构建标准与数据契约

> 当前基线：Pipeline v11 安全默认值 + 内容库 schema **v14**。
> 适用范围：教材、讲义、题集、试卷、论文式文档和结构化题库的摄取、治理、检索与生成。
> “必须/不得”是可测试的发布规则，不是 prompt 建议。

权威实现为 `core/models.py`、`storage/schema.sql`、`storage/query.py`、
`pipeline/extraction_harness.py`、`pipeline/stages/`、`pipeline/concept_linker.py` 和
`pipeline/evaluation.py`。物理表与迁移细节见
[`05_数据模型与存储.md`](05_数据模型与存储.md)。

## 1. 数据分层与所有权

| 层 | 权威内容 | 覆盖策略 | 目标 |
|---|---|---|---|
| 来源层 | 原文件、adapter/VLM Markdown、stage mirror、locator、marker ledger | 不覆盖；内容 hash 形成新 checkpoint | 可重放、可审计、不丢原文 |
| 规范层 | `knowledge_points/questions/figures/item_relations` | 只经验证过的 pipeline 或生成发布路径 | 紧凑检索与后续加工 |
| 语义层 | concept 四表、discipline tag tree | 稳定 id；alias/关系可增量追加 | 跨书归一与图谱 |
| 治理层 | `ingestion_status/item_evaluations/review_queue` | 状态转换与版本化追加 | 发布门禁与人工闭环 |

原始文档、完整 block 和图片二进制不复制到 SQLite。规范正文必须通过
`source_file + page + line/char span` 回溯；`figures` 只保存资产路径、caption 与页码。

## 2. 全局不可破坏不变量

1. **强 marker 100% 有去向**：定义、定理、例题、练习、问题、证明、答案、独立编号与结构化
   记录都进入 ledger。结果只能是已提取、确定性解释或显式 review，不能静默消失。
2. **条目边界独立可引用**：共用一个编号且不可独立引用的题干与选项属于一条；有独立编号或
   独立结论的子题分别成条，并用 item relation 保留结构。
3. **题答不混写**：题干/陈述在 `content`，来源证明在 `proof_content`，来源解答在
   `solution_content`。章末答案由 linker 回填，不创建伪知识点。
4. **不把生成内容冒充来源**：原文缺答案时保持空值并降低 completeness；模型补写只能作为
   显式生成产物，写生成元数据。
5. **来源 locator 合法**：`source_file` 非空；行范围正向；字符 span 使用行内左闭右开语义；
   无法精确定位时明确退化为行级，不伪造字符偏移。
6. **顺序稳定**：`order_index` 按最终来源顺序严格递增。并行、局部 patch 和恢复不得改变同一
   logical document 的相对顺序。
7. **类型双维度**：`question_type` 是认知任务，`question_form` 是载体形式；不得用 choice、
   fill_blank 等形式污染 type。
8. **机器身份与展示分离**：`taxonomy_path/concept_id` 是规范身份；tags 是根到叶的有序
   `english:中文` 展示段，不能代替 concept。
9. **不确定内容保留但不发布**：无法完成可靠边界/配对时写 `uncertain/needs_patch`，不能为降低
   LLM 次数而 force-consume 后丢弃。
10. **评价版本化**：特征、权重或门槛改变必须升 `rubric_version`；历史评价只追加。

## 3. 格式处理与资源边界

| 输入 | Task0 默认路径 | 默认 LLM | 必须保留的 locator/结构 |
|---|---|---:|---|
| Markdown / TeX | 原文 block | 0 | 标题、公式、行号 |
| CSV / TSV | 标准 CSV parser → 有界 Markdown table | 0 | record/行范围、引号与嵌入换行 |
| JSON / JSONL | 深度受限树/记录转换 | 0 | key path、record range、错误行 |
| XLSX | 安全读取 OPC ZIP/XML | 0 | sheet、行列、共享字符串、公式/缓存值 |
| HTML | 不执行脚本的结构解析 | 0 | 标题、段落、列表、链接、表格、code/pre |
| EPUB | container→OPF→spine→XHTML | 0 | spine 顺序与 chapter locator |
| TXT / RST | 编码探测与行块切分 | 0 | 原始行范围 |
| 电子 PDF | 文字层探测→PyMuPDF | 0 | 页范围 |
| 扫描 PDF / DOCX / PPTX | VLM 批量转写 | 通常每批 1 | 页范围、公式、图像引用 |
| PNG/JPEG/WebP/GIF | 有界单图 VLM | 每图最多 1，重试除外 | 文件来源与单 block |

ZIP 容器必须先限制压缩文件体积、entry 数、总解压体积、压缩比、绝对路径和 `..` 路径；
结构化输入必须限制字节数、列数、JSON 深度和每 block 行数。超限应返回可诊断错误，不得尝试
把整个文件塞进 prompt。

允许的确定性预处理包括：编码/换行/空白规范化、高置信 OCR 字符替换、编号规范化、标题与
题型 marker 定位、括号/LaTeX 配平检查、表格结构转换、内容 hash 和重复候选筛选。条件猜测、
语义补写和答案生成不属于预处理。

## 4. 无损提取与 LLM 调用纪律

### 4.1 确定性优先路径

`format_profile → marker ledger → section/genre/structure signals → adaptive window → extraction`
先生成结构证据。干净结构化输入不调用 VLM；无强/弱 marker 的窗口可确定性 fast-skip；风险
review、局部 patch 与 evaluator 只处理具体缺口。

### 4.2 何时允许额外 LLM

- Stage1 主提取：每窗口批量返回所有完整条目；不得为每个 marker 单独调用；
- Stage1Review：只在边界、题答、类型或结构风险信号成立时调用；
- local patch：只给 missed marker 的 ±context span，不重跑整窗；
- Stage2Annotate：同一 block 小批标注，复用 tag/taxonomy 快照；
- Stage2Review：默认关闭，只有配置或风险要求时启用；
- multi-turn validator：默认关闭，仅高风险窗口且 provider 支持时开启。

所有 LLM 响应必须用窄 Pydantic schema、受控 `max_tokens`、retry feedback 和截断检测。静态
system 指令使用 prompt cache；提取/分类使用小 thinking budget，复杂求解才使用大预算。

### 4.3 终端兜底

如果文末、force-extract、重试耗尽或 micro-patch 后仍有未解释的强 marker/非空 span，Stage1
必须构造保留原始 span 的 `uncertain_fragment` 或题/知识占位并入库。该兜底只保证无损，不把
片段宣称为语义正确；治理层会阻止其进入生成池。

## 5. 规范条目规则

### 5.1 KnowledgePoint

允许类别最终由 `DisciplineSpec.allowed_kp_types` 决定，通用集合包括 definition、axiom、
theorem、lemma、proposition、corollary、formula、property、method、remark、example。

- `content` 必须含完整条件、量词、符号定义和结论，不能只保存标题；
- `proof_content` 只保存来源证明；无证明为 `NULL`；
- `number` 逐字保存，canonical/seq 字段确定性派生；
- 无法确定细分 taxonomy 时回退到合法学科根并进入 review，不能选择一个“看起来像”的分支；
- 独立例题若需要作答，应建 Question；纯说明性 worked example 可建 KnowledgePoint，必须由
  类型规则和正文结构共同判断。

### 5.2 Question

- `content` 必须包含独立作答所需的题干、数据、子问和图表引用；
- choice 选项只在 `options` 按原顺序保存，题干不重复；`correct_option` 只保存标签；
- fill blank 用 `blanks` 记录空位数；未知答案为 `NULL`，不得猜测；
- `solution_content` 保存来源答案/推导；仅最终答案可保留，但 completeness 下降；
- 生成题必须写 model/time/session/tenant，成功且验证通过后才 materialize 到题库；
- 同正文去重在 tenant 作用域执行，公共库仍是 `tenant_id=''` 的全局域。

### 5.3 Concept 与关系

- concept id 从合法 taxonomy 稳定派生；alias 只在 `discipline + branch` 唯一；
- item 可通过 `primary/defines/uses/prerequisite/tests` 关联多个 concept；
- concept 状态为 pending/deprecated 时，关联 item 不能发布；
- item relation 与 concept relation 都必须记录 source、confidence；结构规则不能伪装成 LLM
  或人工证据；
- 高置信结构边可自动写，低置信关系进入 review，不为“图更密”而制造边。

## 6. 分领域最低完整性

### 6.1 数学

- 定义保留定义域、量词、等价条件与符号约定；
- 定理/引理保留所有假设和结论；proof 与 statement 分离；
- 公式保持 LaTeX 环境、上下标、矩阵维度、编号与适用条件；
- 多种解法在 solution 内分节保序；“显然/类似”可原样保留但不能替代缺失正文；
- 几何图不是条件替代品，显式条件必须转写；证明题可选 Lean，但形式化翻译仍需一致性审核。

### 6.2 物理

- 数值、单位、有效数字、方向/坐标系、初始和边界条件不得丢失；
- 常数取值、近似假设和适用范围必须在同条目可见；
- 实验题区分装置、步骤、变量、观测、误差与结论；
- 解答最终量带单位，量纲、极限情形和守恒失败进入复核。

### 6.3 化学

- 方程式保留系数、价态/电荷、物态、条件、催化剂和可逆符号；
- 结构式、谱图、装置写 figure，同时保留可检索物质名与条件；
- 计算保留物质的量、浓度、温压和有效数字，答案检查质量/电荷/原子守恒；
- 机理步骤必须有序，不得压成无序 tags。

### 6.4 生物

- 区分实体、结构、过程、调控、证据与结论，避免近似词误合并；
- 实验题保留自变量、因变量、对照、样本、重复、观测和结论边界；
- 通路图、系统发育树与图谱保留 caption/page，正文能独立解释关键标注。

### 6.5 计算机与 other

未注册领域先落 `other`，正式扩展必须新增 DisciplineSpec 与 taxonomy，不能长期依靠自由字符串。

- 编程题保留 I/O、约束、样例、语言/运行环境与资源限制；
- 解答区分算法、正确性、复杂度与代码，代码保留 fenced language；
- 人文/社科资料区分主张、证据、引用和语境；模型改写不得冒充原始引文。

## 7. 题型与形式专项规则

| 类型/形式 | 最低字段 | 确定性检查 |
|---|---|---|
| `choice/multiple_choice` | 题干、全部选项、来源答案标签（若有） | 标签唯一、数量、标签在范围内 |
| `fill_blank` | 完整句/式、空位数、来源答案 | `blanks >= 1`、答案数量兼容 |
| `true_false` | 可判定命题、来源答案 | 不把解释段当命题 |
| `calculation` | 数据、单位、求解目标 | 单位/量纲、容差、代入复算 |
| `proof` | 假设、结论、证明要求 | 数学配平、关键蕴含；可选 Lean |
| `construction` | 对象、约束、允许操作 | 构造后逐条验约束 |
| `experiment_design` | 目标、材料、变量、步骤、指标、安全 | 对照、重复、可观测性 |
| `programming` | I/O、约束、样例、资源上限 | sandbox、边界样例、复杂度 |
| `short_answer` | 问题边界和评分点 | 答案覆盖评分点，不强造长推理 |

领域 spec 可以收窄这张表；不能仅因通用表出现某类型就允许该领域使用。

## 8. 质量评价与发布门禁

`pipeline_auto` 默认开启且不调用 LLM，写入 extraction quality、solution/proof completeness、
10 维 difficulty、Bloom cognitive level、prerequisite depth、proof complexity、lecture suitability、
cross-book generality、source/confidence/rubric/time。

以下情况创建 review task：非 accepted ingestion、低质量、题答/证明不完整、pending concept、
配平失败、编号/marker 覆盖异常、跨段合并不确定。队列只控制发布，不删除来源证据。

默认发布查询在 SQL 层、排序/limit 前强制：

1. `ingestion_status='accepted'`；
2. 没有关联 `pending/deprecated` concept；
3. 当前 rubric 没有 `open/in_progress` review task；
4. 当前 `rubric_version + source` 的 extraction/solution 分数达标。

QGen ContextRetriever、知识搜索、推荐和组卷都传入同一 `QualityGateFilter`。离线旧语料只在
整个 kind/rubric/source 尚无评价时允许 corpus-wide fallback；认证租户题目读取要求显式评分。
`resolved/dismissed` review 不再阻断，但审计历史保留。

## 9. 验收指标

| 指标 | 发布门槛 |
|---|---:|
| 强 marker 去向覆盖率 | 100% |
| 非空未消费尾部 | 0；否则必须有 uncertain 占位 |
| 来源 span 合法率 | 100% |
| `order_index` 倒退 | 0 |
| 未解释编号间隙 | 0；报告中的显式例外除外 |
| 选择题选项截断 | 0 |
| 有来源答案但未配对 | 0 |
| 非法 tag/taxonomy 根 | 0 |
| active alias 跨分支冲突 | 0 |
| 非 accepted/pending/open-review/低分 item 进入默认生成池 | 0 |
| required verifier 为 unavailable/error 却显示 verified | 0 |

## 10. 运行与最终审计

```bash
# 摄取；结构化格式 Task0 默认 0 LLM
uv run sciforge parse run <file-or-directory> --db data/sciforge.db

# 仅在 checkpoint/schema 不兼容或明确全量重建时
uv run sciforge parse run <path> --restart

# 脏文字层扫描 PDF 才强制 VLM
uv run sciforge parse run <pdf> --force-vlm

# 只读验收
uv run sciforge parse validate data/sciforge.db
uv run sciforge parse db-stats data/sciforge.db
```

“摄取完成”必须同时核对最终 `state.json`、failed batches/blocks、marker/numbering/reconciliation
报告、四种 ingestion 状态、pending concept、open review、评价覆盖、数据库 item/FTS 数与来源
locator。只检查 LLM 返回或进程退出码不构成知识库验收。
