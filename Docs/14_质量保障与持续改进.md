# 质量保障与持续改进

> 版本: v2.0 | 日期: 2026-03-31 | 阶段: 贯穿全周期

## 1. 核心质量指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 生成成功率 | 通过验证的题目 / 总候选 | > 50%（各学科） |
| 人工通过率 | 人工审核通过 / 生成总数 | > 80% |
| 学科正确率 | 无误的 / 生成总数 | > 95%（数学），> 90%（物理/CS） |
| 难度校准误差 | \|AI - 人工\| 均值 | < 1.5 |
| 去重有效性 | cosine > 0.92 的比例 | < 5% |
| 解答正确率 | 解答无误 / 总数 | > 90% |
| 知识点提取准确率 | 标签正确 / 总提取数 | > 85% |
| 学科识别准确率 | 学科+学段标注正确 / 总数 | > 95% |

---

## 2. 验证层次

### 2.1 生成时验证（实时）

5 项检查（详见 `03_核心生成引擎.md`）: 求解置信度、数学正确性、非平凡性、LaTeX 语法、解答相关性。

### 2.2 批次后验证

- 去重检测: embedding cosine > 0.92 → 标记重复
- 难度分布分析、覆盖率分析、异常检测

### 2.3 人工审核

自动进入审核队列的条件: 求解置信度为 medium、难度偏差 > 2、首次出现的专题、用户举报、多人做错率 > 80%。

---

## 3. 反馈循环

### 3.1 用户反馈

做题结果 → 更新题目质量分 → 多人标记错误时进入审核队列 → 举报直接进入队列

### 3.2 教师反馈

审核通过 → `verified=true` | 修改 → 记录历史供 LLM 学习 | 拒绝 → 更新负面示例

### 3.3 Prompt 持续改进

定期从审核通过的高质量题目更新 few-shot 示例，从被拒绝题目更新负面示例。

---

## 4. 难度校准模型

| 阶段 | 方法 |
|------|------|
| MVP | 直接使用 LLM 10 维加权评分 |
| 数据积累（50+ 人工评分） | 线性回归: human = α × ai + β |
| 成熟 | 按科目/专题分别校准，跟踪偏差趋势 |

## 7. 可扩展性

### 7.1 新学科接入流程

接入新学科（如化学、生物）的标准化流程:

| 步骤 | 内容 | 预估耗时 |
|------|------|---------|
| 1 | 在 `config/subjects.json` 注册学科，添加 `Subject` 枚举值 | 10 分钟 |
| 2 | 在 `config/subject_tags/` 添加学科标签配置 | 1 小时 |
| 3 | 在 `prompts/subjects/` 添加学科特定 prompt 模板（生成/求解/验证/标注） | 2-4 小时 |
| 4 | 编写学科特定的验证规则（如物理需量纲检查） | 1-2 小时 |
| 5 | （可选）导入学科教材数据 | 变动 |
| 6 | （可选）添加学科 LaTeX 宏定义和文档模板 | 1 小时 |

> 核心 Pipeline、生成引擎、存储层代码**无需修改**。新学科完全通过配置和 prompt 接入。

### 7.2 其他扩展

- **新 LLM 后端**: 在 `llm/backends/` 添加 + 注册枚举 + 配置 key
- **新文档模板**: 在 `templates/` 添加 .tex + 注册
- **新教育阶段**: 在 `EducationLevel` 枚举添加（如 `middle_school`）
- **新题型**: 在 `QuestionType` 枚举添加 + 学科 prompt 中增加示例
