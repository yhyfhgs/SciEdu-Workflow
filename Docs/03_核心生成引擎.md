# 核心生成引擎

> 版本: v2.0 | 日期: 2026-03-31
>
> ⚠️ **历史设计参考**：当前实现见 [`Docs/16_Agent系统MVP.md`](./16_Agent系统MVP.md) 与
> [`Docs/22_QGen_Harness_架构与验证协议.md`](./22_QGen_Harness_架构与验证协议.md)。QGen 已从
> 固定五段直线扩展为可恢复状态图，含 deterministic prefilter、diagnose/evolve、population
> selection、deep solve、数值/Lean 四态证据。本文后续路径和字段可能已失效，不是实现契约。

> 生成引擎架构设计为**学科可配置**——核心 5 阶段流水线对所有学科通用，学科特定行为通过 prompt 模板和验证规则注入。MVP 阶段聚焦大学数学题目生成，但引擎本身支持任意学科的题目与解答生成。

## 1. 架构概览

5 阶段流水线，每阶段输入输出均为 Pydantic 模型（含 `subject_domain` 和 `education_level` 字段）:

```
GenerationRequest (Pydantic)
    │
    ▼
[Stage 1: ContextRetriever] → ContextBundle
    │
    ▼
[Stage 2: QuestionGenerator] → list[Question]  (每轮 3 候选)
    │
    ▼
[Stage 3: SolveEngine] → Solution  (过滤 confidence=="low")
    │
    ▼
[Stage 4: VerificationPipeline] → VerificationResult
    │                               未通过 → 反馈给 Stage 2
    ▼
[Stage 5: DifficultyAnnotator] → DifficultyScore (10 维)
    │
    ▼
GeneratedQuestion (Pydantic)
```

**主循环**: 最多 3 轮，每轮 3 候选，温度递增（0.7 → 0.8 → 0.9）。

---

## 2. Stage 1: 上下文检索

文件: `core/retriever.py`

`ContextRetriever` 从存储中构建 `ContextBundle`，自动按 `subject_domain` + `education_level` 范围检索:
- **知识点**: 按学科+标签匹配 + 难度窗口 [target-3, target+1]，最多 8 个
- **参考题目**: 6 道同学科同学段难度接近的同主题题 + 1 道简单锚点 + 1 道困难锚点
- **负样本**: 仅变式模式，找同主题同题型已有题（最多 5 道）
- **跨学科关联**: 可选——检索关联学科的知识点（如数学分析 ↔ 理论力学）

> Post-MVP 将使用 sqlite-vec 向量检索替代纯标签过滤。

## 3. Stage 2: 题目生成

文件: `core/generator.py`

### 八种变式策略

| 策略 | 编号 | 描述 | 适用学科 |
|------|------|------|---------|
| 参数替换 | A1 | 保持结构，替换数值/函数/物理量 | 全部 |
| 方法迁移 | A2 | 同知识点，不同解法 | 全部 |
| 题型转换 | A3 | 计算→证明、正向→反例、定量→定性 | 全部 |
| 升阶 | A4 | 特殊→一般，增加复杂度 | 全部 |
| 降阶 | A5 | 一般→特殊，添加辅助条件 | 全部 |
| 逆向 | A6 | 反转因果关系 | 全部 |
| 专题生成 | B1 | 围绕指定专题自由设计 | 全部 |
| 交叉综合 | B2 | 融合 2-3 个专题（可跨学科） | 全部 |

LLM 输出 JSON: `content_latex`, `solution_sketch`, `knowledge_points_used`, `methods_required`, `estimated_difficulty`, `design_rationale`, `subject_domain`, `education_level`。

> **学科适配**: 每种策略的 prompt 模板按学科维护。数学侧重定理/证明，物理侧重受力分析/实验设计，CS 侧重算法/复杂度分析。

## 4. Stage 3: 求解引擎

文件: `core/solver.py`

使用 LLM (temperature=0.0) 生成分步解答。通用要求:
1. 逐步推导，每步引用相关知识点（定理/定义/定律/原理）
2. 关键步骤标注 `[关键步骤]`
3. 证明题以 `$\square$` 结尾，计算题给出 `$\boxed{...}$`
4. 自检：是否用到所有条件

学科特定要求通过 prompt 注入:
- **数学**: 引用定理/定义，严格逻辑推导
- **物理**: 画受力图/电路图描述，标注物理量单位，数值验证量纲
- **CS**: 伪代码 + 复杂度分析，注明算法正确性论证

输出 `Solution`（含 confidence: high/medium/low）。

---

## 5. Stage 4: 验证流水线

文件: `core/verifier.py`

### 五项验证检查

| 检查项 | 方法 | 判定标准 |
|--------|------|----------|
| solve_confidence | 检查 Solution.confidence | `in ("high", "medium")` |
| math_correctness | 独立 LLM 审核 | verdict == "PASS" |
| non_trivial | 长度+结构检查 | > 30 字符 + 含数学环境 |
| latex_valid | LaTeX 解析 | 括号匹配、命令有效 |
| solution_relevant | LLM 评判 | 解答与题目相关 |

验证失败时 `suggestions` 注入下一轮 `ContextBundle.feedback_from_previous_round`。

---

## 6. Stage 5: 难度标注

文件: `core/annotator.py`

10 维评分:

| 维度 | 权重 |
|------|------|
| concept_count | 0.15 |
| step_count | 0.15 |
| abstraction_level | 0.12 |
| technique_novelty | 0.12 |
| condition_parsing | 0.10 |
| proof_structure | 0.10 |
| computation_load | 0.08 |
| prerequisite_depth | 0.08 |
| multi_representation | 0.05 |
| metacognition | 0.05 |

综合分 = Σ(维度 × 权重)，存储在 `DifficultyScore.overall`。

## 7. 实现文件

| 文件 | 职责 |
|------|------|
| `core/engine.py` | GenerationEngine 主循环（学科无关） |
| `core/retriever.py` | 上下文检索（按学科+学段过滤） |
| `core/generator.py` | 题目生成 |
| `core/solver.py` | 求解 |
| `core/verifier.py` | 验证（含学科特定规则） |
| `core/annotator.py` | 难度标注 |
| `prompts/templates.py` | 核心提示词 |
| `prompts/strategies.py` | 策略指令 |
| `prompts/subjects/` | 学科特定 prompt 模板目录（math/, physics/, cs/ 等） |
